# 图像定价工作台设计

## 1. 背景与目标

当前 `/system-settings/billing/image-pricing` 页面要求管理员直接编辑 `ImageModelCatalog` 与 `ImageRoutingPolicy` 两段 JSON。配置内容同时包含模型能力、SKU 规格、上游成本映射后的展示信息、用户售价和路由策略，日常改价需要理解内部结构，容易漏逗号、改错 SKU 或误触能力配置。

本设计将页面主流程改为“图像 SKU 表格快速改价”，让管理员在同一张表中查看和修改可售 SKU 的用户售价，并在保存前看到成本与预计毛利率。高级 JSON、路由策略、导入导出及兼容性测试继续保留在折叠的“高级设置”中，满足故障排查和批量维护需求。

目标如下：

- 日常改价不需要手写 JSON；单元格可直接编辑，支持一次提交多行变更。
- 每行明确展示模型、尺寸、质量、上游成本、用户售价、预计毛利率和启用状态。
- 保留现有 `ImageModelCatalog`、`ImageRoutingPolicy` 配置键和后端校验，不迁移历史数据，不改变历史计费快照。
- 保存成功后刷新目录、路由预览和页面状态；失败时保留未保存输入并逐项显示错误。
- 继续支持 `manual`、`lowest_cost`、`cost_weighted` 三种路由策略及其现有语义。

非目标：本次不新增渠道成本录入模型、不改变成本规则表、不自动根据上游价格改变售价、不把原生 Gemini `generateContent` 伪装成 OpenAI Images 路由，也不重写图像转发协议。

## 2. 信息架构与页面布局

页面标题保持“图像模型与路由”。主区域由以下部分组成：

1. **工具栏**：显示 SKU 总数、已启用数量、未保存变更数量；提供“刷新”和“保存更改”按钮。没有变更时保存按钮禁用，保存期间防止重复提交。
2. **SKU 表格**：每个模型按模型名分组，每组列出该模型端点下的 SKU。列顺序固定为：模型、端点、尺寸、质量、上游成本、用户售价、预计毛利率、启用状态。
3. **状态提示**：保存成功显示最后保存时间；保存失败显示表单级错误，同时保留用户编辑内容。
4. **高级设置**：使用可展开面板，包含原有 JSON 编辑器、路由策略 JSON、路由预览、导入/导出和兼容性测试。默认收起，不影响改价主流程。

表格行使用稳定的 `model + sku key` 标识。上游成本为只读，来自当前已激活成本规则对渠道映射的聚合结果；没有可用成本时显示“未配置”，不把未知成本当成 0。用户售价为美元定点字符串，展示为 `$0.0000`（去除无意义尾零），输入框保留可精确编辑的原始小数。

## 3. 数据与兼容性

### 3.1 前端行模型

前端将 `ImageModelCatalog` JSON 解析为表格行，并保留每行到原始模型/SKU 的路径：

```ts
type ImagePricingRow = {
  id: string
  model: string
  endpoint: string
  size: string
  quality: string
  skuKey: string
  salePriceUSD: string
  upstreamCostUSD?: string
  expectedMarginBps?: number
  enabled: boolean
}
```

`enabled` 表示该 SKU 是否可被目录解析和路由选择。现有目录格式没有独立的 SKU 启用字段，因此保存时通过现有结构表达禁用状态（移除该 SKU 或关闭对应端点能力）必须由高级设置完成；表格主流程只编辑已存在 SKU 的售价，启用状态只读展示。这样避免为了一个 UI 字段改变后端目录协议。

### 3.2 保存格式

表格保存时只修改对应 `SKU.sale_price_usd`，再按原目录结构序列化并调用现有系统选项更新接口：

- key `ImageModelCatalog`：提交完整、校验过的目录 JSON。
- key `ImageRoutingPolicy`：仅在高级设置中编辑并保存；表格保存不重写路由策略。

保存前使用与后端一致的定点价格约束：非负、有限小数、不能是空值；前端错误必须定位到具体行。最终合法性以 `setting/image_setting/catalog.go` 的 `ValidateCatalog` 为准。更新失败时不得清空 dirty 状态或用服务端旧值覆盖输入。

### 3.3 成本与毛利

表格只读成本数据通过现有成本规则查询/汇总接口获取，并按 `channel + 映射后上游模型 + SKU` 匹配。多个渠道属于同一 image 分组时，表格可以展示“最低已知成本”和成本来源数量，但不改变路由选择：

- `lowest_cost`：按当前 active 成本规则排序，成本相同再比较 Priority，最后比较 Weight；低价渠道通常承接正常流量，高价渠道仅在低价候选不可用时回退。
- `manual`：沿用现有 Priority 分层，同一 Priority 内按 Weight（含现有实现的 baseline 规则）加权；Priority 不是流量比例。
- `cost_weighted`：沿用当前成本容忍区间和最低毛利率约束，不在本页面重新计算或改写其策略。

预计毛利率按用户售价和选中成本计算：`(sale - cost) / sale`。售价为 0 或成本未知时显示“无法计算”，不会显示负数或把异常值静默转换为有效价格。页面提示成本是供应商成本规则的配置值，不声称为自动读取的真实账单。

## 4. 交互流程

### 4.1 快速改价

1. 页面加载目录和成本摘要，生成稳定排序的表格行。
2. 点击用户售价单元格，进入输入状态；输入框支持键盘编辑和 `Enter` 确认单元格、`Escape` 恢复原值。
3. 修改后的行显示 dirty 标记，工具栏显示未保存数量；离开页面或收起设置时若有 dirty 状态，使用浏览器离开确认。
4. 点击“保存更改”后，先执行全部行校验，再一次性提交目录。提交期间禁用表格编辑和重复保存。
5. 成功后重新拉取系统选项和成本摘要，清除 dirty 状态，并刷新高级设置中的路由预览选择项。失败时显示接口错误，保留所有修改。

### 4.2 高级设置

高级设置沿用现有 JSON 编辑器和路由预览能力，但拆分为两个明确面板：

- **目录 JSON**：用于新增模型、端点、能力、SKU、响应格式等表格不覆盖的配置。保存前展示“这会影响表格行”的提示。
- **路由与验收**：编辑路由策略，选择分组/模型/端点/尺寸/质量后执行预览；展示候选渠道、预计成本、排除原因和最终选择。兼容性测试继续调用现有验收接口，结果不自动写入目录。

导入/导出操作仅作用于目录 JSON，导入后先进入 dirty 状态并执行本地校验，必须点击保存才写入系统选项。导出内容包含当前目录版本和生成时间，但不包含渠道密钥或敏感成本规则详情。

## 5. 后端接口与实现边界

优先复用现有系统选项读取/更新接口和图像路由预览接口，不新增持久化表。若当前成本摘要接口不能按 SKU 返回所需字段，新增只读管理接口，返回模型/SKU 维度的已激活成本聚合与来源数量；该接口不得返回渠道密钥，且需遵循现有管理员鉴权。

前端解析和序列化应集中在图像定价页面的纯函数中，避免修改 `setting/image_setting` 的目录语义。后端继续负责最终目录校验、价格格式校验和原子更新。更新两个系统选项时，目录更新成功而路由更新失败的情况必须在 UI 中明确显示；表格保存只更新目录，因此不会产生跨键部分成功。

## 6. 错误处理与安全约束

- 无法解析目录：显示页面级错误和“打开高级目录 JSON”入口，不渲染空表格，避免误保存覆盖。
- SKU 价格为空、负数、非数字或精度超限：定位到对应单元格，阻止提交。
- 成本查询超时：仍可编辑售价，但毛利率显示“暂不可用”，保存不依赖成本接口成功。
- 更新接口返回失败：显示服务端消息，保留 dirty 行；不重试可能造成重复写入的请求。
- 权限不足：禁用编辑和保存，仅允许查看高级 JSON 与预览（由接口权限结果决定）。
- 任何价格计算不得产生负收费或溢出；展示计算使用安全的定点/十进制运算，不能用不受控的浮点转整数。

## 7. 测试与验收

### 7.1 前端单元与组件测试

- 目录 JSON 展平和回写：多模型、多端点、多 SKU 顺序稳定，除售价外字段字节级语义不变。
- 售价校验：空值、负数、非数字、超出允许精度被拒绝；合法 0 价格可按业务规则明确处理并显示无法计算毛利。
- 编辑交互：Enter/Escape、dirty 计数、批量保存成功/失败、失败后保留输入。
- 成本未知、售价低于成本、成本相等等情况下毛利展示正确且不会出现 NaN/Infinity。
- 高级设置展开后，现有路由预览和 JSON 保存行为保持可用。

### 7.2 后端回归

- 继续运行 `setting/image_setting` 目录校验测试和图像路由策略测试。
- 验证系统选项更新后目录缓存刷新，历史计费日志中的快照不受影响。
- 如新增成本摘要接口，覆盖 SQLite、MySQL、PostgreSQL 兼容的查询路径及管理员权限。

### 7.3 浏览器验收

在 `http://127.0.0.1:3000/system-settings/billing/image-pricing` 完成：加载现有 `gpt-image-2` 的 1K/4K SKU、修改两行售价、刷新后值保持；展开高级设置执行一次路由预览；验证窄屏表格横向可滚动、输入文字不溢出、保存按钮状态和错误提示清晰。

## 8. 发布与回滚

本次发布只涉及前端页面和必要的只读成本摘要接口，不需要数据库迁移。旧版 JSON 配置仍是唯一事实来源，回滚前端即可恢复旧编辑方式。若新页面解析异常，自动降级为高级目录 JSON 编辑器并保留原始配置，避免阻断管理员修复。

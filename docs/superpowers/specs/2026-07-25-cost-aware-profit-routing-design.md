# 基于预计毛利率的渠道模型准入设计

## 1. 背景与目标

当前渠道模型成本已经支持按次、按时长、按 Token 和显式免费四种结构化模式，但路由只判断渠道能力、模型映射和成本覆盖，不判断本次请求是否可能亏损。

按次成本模型会因此在短时长请求中被选中。例如：官方售价为 0.99 元/秒，用户分组倍率为 0.5，渠道成本为 5 元/次。用户请求 5 秒时，预计用户收入为 2.475 元，预计利润为 -2.525 元；请求 11 秒时，预计收入为 5.445 元，预计利润为 0.445 元。

本设计增加“最低预计毛利率”准入策略：只有预计毛利率达到配置值的渠道模型才进入候选。该策略同时覆盖四种成本模式，并通过独立视频元数据服务取得输入视频时长，避免由 new-api 网关承担媒体下载流量和解析压力。

目标：

1. 按用户官方售价、实际分组倍率和请求事实预测收入。
2. 按活动渠道成本规则预测本次请求成本。
3. 只允许 预计毛利率 >= 生效最低毛利率 的候选进入原有渠道选择逻辑。
4. 在真正发送上游前再次权威复核，避免配置变化造成绕过。
5. 普通用户不能看到渠道成本、利润、阈值或排除原因。

非目标：

- 第一阶段不改变已有渠道优先级、权重和随机选择语义。
- 第一阶段不按预计利润重新排序渠道。
- 第一阶段不把供应商成本写入用户售价规则。
- 第一阶段不引入本地 Excel/CSV 自动导入；价格仍由管理员手工配置。

## 2. 已确认的业务规则

### 2.1 毛利率

    预计毛利率 = (预计用户收入 - 预计渠道成本) / 预计用户收入

当预计用户收入为 0 时，毛利率为空，候选直接排除。候选准入使用包含边界的比较：

    预计毛利率 >= 最低预计毛利率

最低预计毛利率的允许范围为 0%～100%，不允许负值。

失败重试按每个候选 attempt 独立判断。已经发生的失败 attempt 成本只进入实际成本账本，不反向放宽或收紧后续候选准入。

### 2.2 配置继承

- 系统设置提供全局默认最低预计毛利率。
- 路由目标可以配置可空覆盖值。
- 路由目标覆盖值为空时继承全局值。
- 路由目标显式配置 0% 时表示允许零毛利，不能被误认为未配置。

### 2.3 未知数据

无法可靠计算预计用户收入或预计渠道成本时，严格排除该候选。未知成本不能解释为零成本。

## 3. 数据结构

### 3.1 阈值配置

全局成本设置增加：

    minimum_expected_margin_bps int

路由目标表 route_targets 增加可空字段：

    minimum_expected_margin_bps *int

基点定义：

| 存储值 | 含义 |
|---:|---:|
| 0 | 0% |
| 1000 | 10% |
| 10000 | 100% |

数据库保存整数，管理界面按百分比输入和显示，最多两位小数。后端保存时校验 0 <= value <= 10000。使用指针区分 NULL 继承和显式零值。

阈值进入路由目标写入 DTO、查询视图和路由策略缓存快照。保存、启停、删除路由策略时刷新对应的分组和模型缓存。该字段为普通数据库列，迁移必须同时兼容 SQLite、MySQL 和 PostgreSQL。

### 3.2 请求级预测快照

请求级内部事实快照至少包含：

- 客户端原始模型和生效用户分组；
- 输出分辨率、宽度、高度和帧率；
- 请求输出时长；
- 输入视频总时长；
- 预计输入 Token、输出 Token 和总 Token；
- 元数据解析来源、时间和可信状态。

该快照只在当前请求内流转，不写入路由策略表。候选评估结果额外保留管理员诊断所需的阈值、成本规则 ID/版本和排除原因。

### 3.3 成本规则

成本规则继续只描述供应商成本，沿用现有 CostRuleConfigV1 和活动版本机制：

- free；
- per_request；
- per_duration；
- per_token。

原币价格、换算参数和标准化 USD 价格继续按现有成本设计保存。候选预测和 attempt 结算都使用标准化金额；不使用二进制浮点比较金额。

## 4. 预计收入与成本计算

### 4.1 预计用户收入

预计收入必须复用现有官方售价计费链路，以客户端 OriginModelName、实际生效分组倍率和已经校验的请求参数计算用户最终预计扣费，再通过现有配额单位快照换算为 nano-USD。

不能根据渠道映射后的供应商模型重新查用户售价，也不能在路由层复制一套简化的售价公式。表达式计费必须继续遵循 pkg/billingexpr/expr.md 的变量、版本和配额转换契约。

### 4.2 按次成本

    预计成本 = 标准化单次价格 × 1

这会自然形成按次成本的最小时长门槛。例如：

    最小时长 = ceil(单次成本 / (官方每秒售价 × 用户分组倍率 × (1 - 最低毛利率)))

当最低毛利率为 0% 时，5 / (0.99 × 0.5) 向上取整为 11 秒；当最低毛利率为 10% 时，结果为 12 秒。实际实现不直接使用该公式推门槛，而是使用统一金额预测逐候选计算，避免不同售价模式出现两套逻辑。

### 4.3 按时长成本

    预计成本 = 标准化每秒成本 × 预计可计费输出时长

候选阶段使用已校验的请求时长。实际 attempt 仍按照成本规则声明的计量来源（例如 validated_request 或 upstream_actual）结算。不得在结算时静默切换计量来源。

### 4.4 按 Token 成本

输入视频时长由网关调用独立元数据服务取得。对 Seedance 视频模型，预计 Token 使用以下公式：

    input_tokens  = 输入视频总时长 × 输出宽 × 输出高 × 帧率 / 1024
    output_tokens = 请求输出时长 × 输出宽 × 输出高 × 帧率 / 1024
    total_tokens  = input_tokens + output_tokens

多段输入视频的时长求和。中间计算使用 Decimal，最后生成供应商成本计量时统一向上取整，避免因小数截断低估成本。

对应成本规则子模式：

- total_tokens 使用预计总 Token；
- completion_tokens 使用预计输出 Token；
- input_output 分别使用预计输入和输出 Token。

所有数量在进入成本计算前必须受安全上限约束；不得使用未经限制的 int(float64(...)) 或类似裸转换。若估算结果无法证明可靠，候选排除。

### 4.5 免费成本

    预计成本 = 0

只要预计用户收入大于零，预计毛利率为 100%。没有活动规则不能推断为免费。

### 4.6 金额比较

复用现有成本预览的金额函数：

- 用户收入转换为 RevenueNanoUSD；
- 渠道成本转换为 CostNanoUSD；
- 利润通过带溢出检查的减法计算；
- 毛利率通过现有 GrossMarginPPM 计算；
- 将基点阈值精确转换为 PPM 后比较，不使用浮点数。

## 5. 请求链路与候选准入

### 5.1 请求级事实

分发前完成请求参数校验并解析路由事实。输入视频元数据只解析一次，结果保存为请求级快照，候选和重试复用该快照。

先执行现有能力约束：清晰度、时长、比例、参考素材数量和真人脸能力。只有能力匹配的目标进入利润评估。

### 5.2 候选阶段

对每个自动分组或指定分组：

1. 使用该分组计算预计用户收入。
2. 获取候选路由目标及其上游模型。
3. 批量读取对应 channel_id + billable_upstream_model 的活动成本规则。
4. 根据成本模式和请求级预测快照计算预计成本及预计毛利率。
5. 使用路由目标覆盖值或全局默认值作为生效阈值。
6. 过滤不满足阈值、收入为零、规则缺失、计量未知或计算失败的候选。

通过的候选交给现有 GetRandomSatisfiedChannel 等选择逻辑，继续使用原有优先级、权重和随机语义，不按利润重新排序。

普通随机、自动分组、渠道亲和、指定渠道和重试入口必须调用同一个利润准入函数，不能存在绕过路径。

### 5.3 发送前复核

在适配器完成模型映射并确认最终 billable_upstream_model 后、创建成本 attempt 和发送上游之前：

1. 重新读取活动成本规则和最新生效最低毛利率。
2. 使用最终上游模型和请求级事实重新计算预计收入、成本和毛利率。
3. 通过阈值后才创建 attempt 快照并发送。
4. 如果配置变化导致不达标，不发送上游，将当前渠道加入请求排除集合并继续重试。

候选阶段和复核阶段规则版本不同不必然失败；只要最新规则通过，就按最新规则创建 attempt 快照。已经开始发送后的成本和重试语义仍遵循现有成本账本设计。

## 6. 独立输入视频元数据服务

### 6.1 架构选择

不在 new-api 进程内下载和解析输入视频。独立服务部署在专属服务器或独立计算节点，由该服务承担媒体源流量、连接数、临时文件、解析 CPU、限流和缓存。

同机 sidecar 只能隔离部分 CPU 和内存，不能隔离出口带宽和故障域，因此不作为目标架构。

new-api 只发送元数据请求和接收结构化结果，不转发视频内容：

    客户端 -> new-api -> metadata-service -> 素材源
                             |
                             +-- duration / width / height / fps

第一阶段使用同步调用，因为候选准入必须在发送上游前得到结果。服务本身可以无状态横向扩展，后续可增加队列或异步预热，但不改变同步准入契约。

### 6.2 内部 HTTP API

采用内部 HTTP JSON，而不是第一期引入 gRPC。请求示例：

    POST /v1/metadata/video
    Authorization: Bearer <service-token>
    Content-Type: application/json

    {
      "url": "https://example.com/input.mp4",
      "media_type": "video",
      "max_bytes": 134217728,
      "deadline_ms": 30000
    }

成功响应只返回结构化元数据：

    {
      "duration_ms": 5200,
      "width": 1280,
      "height": 720,
      "frame_rate_num": 24,
      "frame_rate_den": 1,
      "container": "mp4",
      "content_length": 1834210,
      "etag": "..."
    }

服务间使用 mTLS 或专用服务令牌，不能复用用户 API Key。new-api 必须再次校验响应字段的范围、精度和完整性，并携带最大字节数和截止时间。服务端不能放宽请求限制。

### 6.3 服务端安全边界

第一阶段仅处理 Seedance 请求中的 HTTP(S) reference_video：

- 使用 SSRF 防护客户端，DNS 解析和每次重定向都校验；
- 每个视频最多下载 128 MiB；
- 单个请求全部素材解析最多 30 秒；
- 流数据写入临时文件，不把完整视频载入内存；
- 使用项目已经依赖的 go-mp4 解析 MP4/MOV；
- 校验文件签名，不能只相信扩展名或 Content-Type；
- 解析完成立即删除临时文件；
- 第一阶段不支持 WebM、MKV 等其他容器；
- 时长使用 Decimal 和毫秒精度返回，并受计费安全上限约束。

元数据服务不得记录完整媒体 URL、查询参数或视频内容。服务日志只记录素材序号、解析结果类型、耗时、字节数和失败分类。

### 6.4 缓存与失败

服务端缓存键使用 URL、ETag、Last-Modified 和内容长度组合。带签名参数的 URL 默认使用短 TTL，不能因为缓存而延长敏感链接生命周期。new-api 请求级只缓存本次请求结果，不能跨请求复用未经服务端策略确认的私有素材结果。

- 元数据服务不可用或超时：只排除依赖该元数据的候选；没有其他候选时返回 503。
- 素材无效、格式不支持或超过限制：返回 400，不能按零秒或零 Token 继续。
- 服务响应字段非法、越界或不完整：视为内部元数据错误，失败关闭并记录管理员告警。

## 7. 错误、隐私与可观测性

单个候选被排除时记录管理员诊断原因：

- revenue_unknown；
- cost_rule_missing；
- meter_unknown；
- margin_below_threshold；
- calculation_error；
- metadata_unavailable。

所有候选被利润策略排除时沿用“兼容渠道不可用”类 503。普通用户不能看到最低毛利率、供应商价格、标准化成本、利润、规则 ID/版本、渠道 ID 或排除明细。

输入视频无法安全读取或格式不支持时，在路由前按无效素材返回 400。配置无效、缓存损坏、金额溢出和内部数据矛盾失败关闭，并发送管理员告警。

预计利润信息可以进入管理员专用审计信息，但不得进入普通用户日志、任务公开响应或渠道上游请求。

## 8. 缓存失效与并发一致性

- 全局阈值使用现有原子运行时快照，保存后立即生效。
- 路由目标阈值随路由策略快照刷新。
- 成本规则活动版本按 channel_id + billable_upstream_model 批量读取或缓存，避免候选数量产生 N+1 查询。
- 成本规则激活、停用或版本变化时同步失效对应缓存。
- 发送前复核不依赖候选阶段缓存结果；必须读取当前活动规则和阈值。
- attempt 创建时在同一成本账本事务中保存规则版本、原币参数、换算参数和计量来源快照。

## 9. 管理后台

路由目标编辑增加最低预计毛利率覆盖值，支持：

- 留空继承全局；
- 输入百分比并校验 0%～100%；
- 显示当前继承后的生效值。

全局成本设置增加默认最低预计毛利率。渠道模型成本页面继续展示当前官方售价、原币成本、标准化成本、预计收入、预计成本、预计利润和预计毛利率，但这些内容仅对管理员可见，并明确标记为“预计”或“计费收入等值”，不能称为现金收入或净利润。

独立元数据服务的地址、服务令牌和超时属于运维配置，不暴露给普通用户。第一期可以使用环境变量或现有运维配置机制，具体管理页面不纳入本设计的必要范围。

## 10. 测试计划

### 10.1 预计利润计算

- 按次成本 5 元、官方每秒售价 0.99 元、用户倍率 0.5：0% 阈值下 5 秒排除、11 秒准入。
- 相同输入在 10% 阈值下 11 秒排除、12 秒准入。
- 按时长成本验证线性收入和成本的毛利率，以及请求时长边界。
- 按 Token 成本验证输入、输出、总 Token 和 input_output 子模式。
- 验证多段输入视频时长求和、毫秒转 Decimal 和最终向上取整。
- 免费成本在收入大于零时得到 100% 毛利率。
- 收入为零、Token/时长缺失、规则缺失、计量不支持、金额溢出均严格排除。

### 10.2 路由和复核

- 普通选路、自动分组、渠道亲和、指定渠道和重试全部执行利润过滤。
- 路由目标覆盖值优先于全局值，NULL 正确继承，显式零值不被当作未配置。
- 过滤后保持既有优先级、权重和随机选择结果语义。
- 候选通过后修改成本规则或阈值，发送前复核必须阻止不达标渠道发送并切换候选。
- 所有候选被排除时返回统一 503，普通用户不获得内部原因。

### 10.3 元数据服务客户端

- 成功响应能够生成完整请求快照。
- 超时、服务不可用、格式错误、越界字段和恶意响应均失败关闭。
- 同一请求只调用一次；服务端缓存命中时不重复下载。
- 验证 new-api 不接收或转发视频内容。
- 验证元数据异常不会转换成零秒或零 Token。
- 验证服务令牌不出现在普通日志和管理员业务报表中。

### 10.4 数据库和安全

- SQLite、MySQL 和 PostgreSQL 分别验证新增阈值字段迁移、空值继承和索引查询。
- 验证规则激活、路由策略保存和全局设置变更会立即刷新运行时缓存。
- 验证 URL 查询参数、认证头和视频内容不会写入日志。
- 验证金额计算使用 Decimal、统一 nano-USD 转换和溢出保护。

所有新增 Go 测试使用 require 进行 setup 和致命断言，使用 assert 进行非致命值检查。测试必须是确定性的，不使用随机大输入、sleep 或性能时间比较。

## 11. 发布与降级

1. 先部署独立元数据服务并完成健康检查、SSRF 策略和容量监控。
2. 发布 new-api 的阈值配置、候选过滤和发送前复核，但默认最低阈值为 0，保持原有候选结果尽量不变。
3. 为目标路由逐步设置非零最低毛利率，观察候选排除率、无可用渠道率和实际利润报表。
4. 元数据服务不可用时不得把未知数据当作零成本；可以暂时将依赖输入视频 Token 预测的候选排除，其他无需该元数据的候选继续工作。
5. 发现配置或服务异常时，将全局阈值回退为 0 只能恢复“零毛利也可准入”，不能绕过缺失成本规则、未知成本或发送前复核。

## 12. 验收结论

第一期完成后，系统能够按官方售价定价、以用户分组倍率形成折扣，并针对每个候选渠道模型实时预测成本、利润和毛利率。按次成本模型会根据请求时长自动形成最低准入门槛；按时长、按 Token 和免费成本也使用同一套准入契约。

输入视频元数据由可独立部署、可横向扩展的专属服务解析，new-api 不承担媒体下载带宽和解析 CPU。候选阶段过滤与发送前权威复核共同保证配置变化和重试路径不能绕过最低毛利率策略。

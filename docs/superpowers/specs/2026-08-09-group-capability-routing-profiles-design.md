# 分组能力路由档案设计

## 1. 背景

当前系统已经具备以下基础能力：

- 管理员手动创建上游渠道并配置 API Key。
- 渠道模板导入负责绑定真实渠道、生成 `default` 分组的模型路由策略、路由目标和供应商成本规则。
- 下游账号和 Token 可以分配到不同计费分组。
- 分组路由要求支持 `require_real_person`，运行时会与请求级真人要求合并。
- 严格成本核算和毛利门禁会在真实请求路由时过滤亏损或成本未知目标。

现有分组仍主要承担价格倍率和可见性配置。若运营人员需要为不同下游客户提供不同能力，例如“支持真人素材”“仅使用按次供应商”“仅使用按时长供应商”，当前必须重复配置渠道分组和分组路由策略，无法自动继承渠道模板维护的 `default` 目标池。

本设计将分组扩展为面向下游账号的能力套餐。运营分组不复制 `default` 路由策略，而是保存一层动态能力档案，实时筛选 `default` 路由目标，并提供可审计的适配目标目录。

## 2. 目标

1. 下游账号或 Token 分配到运营分组后，自动获得该分组定义的路由能力边界。
2. 运营分组动态继承 `default` 分组的模型路由策略和目标，不要求渠道重复声明所有运营分组。
3. 支持组合真人能力、供应商成本模式等条件。
4. 条件变化、渠道模板更新、成本规则切换后自动重新计算适配结果。
5. 管理员可以查看每个分组当前匹配、排除和不兼容的路由目标及原因。
6. 管理员可以排除个别已匹配目标，但不能强制加入不满足能力条件的目标。
7. 没有兼容目标时严格拒绝，不回退到不兼容目标。
8. 保持旧分组、旧模板和现有静态分组路由策略兼容。

## 3. 核心业务语义

### 3.1 分组作为能力套餐

账号和 Token 继续使用现有分组分配机制，不新增客户绑定表。实际使用分组确定后，路由层读取该分组的能力档案。

```text
下游账号或 Token
-> 实际使用分组
-> 分组能力档案
-> default 路由目标池
-> 能力和成本模式过滤
-> 人工排除过滤
-> 请求级素材、成本和毛利门禁
-> 最终上游目标
```

### 3.2 条件组合

- 不同条件维度之间使用 AND。
- 同一多选维度内部使用 OR。
- 未配置某一条件表示该维度不限制。
- 人工排除在自动匹配之后执行。
- 人工排除只能减少候选集，不能绕过能力条件增加候选。

例如：

```text
真人能力 = 必须支持
允许成本模式 = per_request 或 per_duration
```

表示目标必须明确支持真人素材，并且当前生效供应商成本规则必须是按次或按时长计费。

### 3.3 真人能力三态

真人能力使用三态枚举：

- `any`：不限制真人能力。
- `required`：只允许明确声明 `supports_real_person=true` 的目标。
- `forbidden`：只允许明确声明 `supports_real_person=false` 的目标。

目标缺少 `supports_real_person` 声明时属于未知能力：

- `any` 可以继续参与其他条件判断。
- `required` 和 `forbidden` 均不匹配。

请求级 `routing.require_real_person=true` 仍然生效：

- 分组为 `any` 时，请求级要求将候选限制为明确支持真人的目标。
- 分组为 `required` 时，结果不变。
- 分组为 `forbidden` 时产生不可满足冲突，严格返回无兼容路由。

### 3.4 供应商成本模式

允许多选以下现有成本模式：

- `per_request`
- `per_duration`
- `per_token`
- `free`

未选择任何模式表示不限制供应商成本模式。选择了一个或多个模式后，目标必须存在对应渠道、上游模型和成本变体的当前生效成本规则，且规则模式位于允许集合中。

以下情况均不匹配：

- 没有生效成本规则。
- 成本规则配置无效。
- 目标指定的成本变体没有对应生效规则。
- 生效规则模式不在允许集合内。

### 3.5 严格拒绝

能力档案生效后，以下情况不得回退到旧渠道选择或不兼容目标：

- 来源路由策略不存在或被禁用。
- 来源策略没有目标。
- 所有目标均能力不匹配。
- 所有目标均成本模式不匹配或成本规则未知。
- 所有匹配目标均被人工排除、禁用或渠道不可用。
- 分组真人能力与请求级真人要求冲突。

普通客户收到现有通用无兼容路由错误；管理员诊断记录具体不匹配原因和数量。

## 4. 配置模型

扩展现有 `GroupRoutingRequirements` 配置，不新增一份重复的分组路由策略表。逻辑结构如下：

```json
{
  "客户分组A": {
    "status": "active",
    "routing_source": "default",
    "real_person_mode": "required",
    "allowed_cost_modes": ["per_duration"],
    "excluded_target_keys": [
      "opaque-server-generated-target-key"
    ]
  }
}
```

字段语义：

- `status`：`draft` 或 `active`。
- `routing_source`：首版自动适配只允许 `default`。
- `real_person_mode`：`any`、`required` 或 `forbidden`。
- `allowed_cost_modes`：供应商成本模式允许集合。
- `excluded_target_keys`：管理员人工排除的稳定目标键。

### 4.1 状态

- `draft`：允许保存和预览，不能参与真实路由。账号误分配到草稿分组时严格拒绝。
- `active`：参与真实路由。激活前必须确认当前至少存在一个静态匹配目标。

激活校验只验证静态能力、成本合同和人工排除结果。请求时长、分辨率、素材矩阵和毛利属于请求级事实，继续在真实请求时判断。

### 4.2 兼容旧配置

- 未配置 `routing_source` 的旧分组继续使用现有分组自身的静态路由策略和渠道能力，不改变行为。
- 旧配置 `require_real_person=true` 兼容解释为 `real_person_mode=required`。
- 旧配置 `require_real_person=false` 或字段缺失兼容解释为 `real_person_mode=any`。
- 新配置保存时写入新字段；读取和导入阶段继续接受旧字段。
- 同一分组同时提供旧字段和新字段且语义冲突时拒绝保存或导入。

### 4.3 配置校验

配置校验必须限制：

- 分组名称非空并符合现有分组名称限制。
- `default` 作为来源目标池，不能配置为继承自身的动态档案。
- `auto` 是请求时的分组选择方式，不是可保存能力档案的实体分组。
- 状态和枚举值属于允许集合。
- `routing_source` 首版只能是 `default`。
- 成本模式去重且只包含系统已支持模式。
- 单分组人工排除项数量、单个键长度和配置总大小有明确上限。
- 未知字段继续使用严格 JSON 解码拒绝，避免拼写错误静默失效。

## 5. 稳定目标标识

数据库路由目标 ID 可能在模板重新发布后变化，不能直接作为人工排除依据。

服务端为每个来源目标生成不透明稳定键，输入至少包含：

```text
来源分组 + 规范模型 + 渠道 ID + 上游模型 + 成本变体 + 目标名称
```

稳定键由服务端规范化并摘要，前端只保存和回传不透明字符串，不自行拼接。

设计原则：

- 同一业务目标在模板重新导入后保留排除状态。
- 上游模型、成本变体或目标名称发生业务性变化时视为新目标，不继承旧排除。
- 已不存在的键保留为失效排除项，并在管理端提示清理。
- 不在键中包含 API Key、渠道密钥或成本价格。

## 6. 运行时路由

### 6.1 来源策略解析

实际分组存在有效动态档案时：

1. 使用 `default + 规范模型` 获取现有路由策略快照。
2. 候选渠道能力判断使用来源分组 `default`。
3. 不要求渠道的 `Group` 字段重复包含运营分组。
4. 不创建或复制运营分组对应的 `RoutingPolicy` 和 `RouteTarget`。

动态档案不存在时，继续使用当前分组自身策略和能力表，保持旧行为。

### 6.2 过滤顺序

建议顺序如下：

1. 来源策略和目标快照有效性。
2. 目标、渠道和来源分组能力是否启用。
3. 真人能力和请求级真人要求。
4. 人工排除。
5. 批量解析当前生效成本规则和成本变体。
6. 供应商成本模式。
7. 现有素材、分辨率、时长和输入模式约束。
8. 现有严格成本核算与最低毛利门禁。
9. 优先级、权重、亲和和重试选择。

能力、成本模式和人工排除属于硬约束，指定渠道、亲和目标和重试均不能绕过。

### 6.3 自动分组

请求使用 `group=auto` 时，每个实际候选分组独立执行：

1. 读取该分组档案。
2. 解析其来源策略。
3. 应用该分组能力条件。
4. 当前分组无候选时继续尝试下一个自动分组。

所有候选分组均无兼容目标时沿用现有无可用渠道错误语义。

### 6.4 模型可见性

客户模型目录必须使用与运行时一致的静态适配解析器：

- 只展示至少存在一个静态匹配目标的模型。
- 某模型所有目标失效后，从该分组目录中隐藏。
- 目录判断不承诺某个具体请求一定通过；实际素材和毛利仍在请求时校验。

## 7. 管理端设计

入口继续位于“系统设置 -> 分组定价”，不新增一级导航。

### 7.1 分组列表

每个分组显示紧凑摘要：

- 档案状态。
- 路由来源 `default`。
- 真人能力三态。
- 允许成本模式标签。
- 当前匹配模型数和目标数。
- 失效排除数和配置警告。
- “查看目标”命令。

未配置 `routing_source` 的旧分组明确显示“旧静态策略”，管理员必须主动开启“从 default 自动适配”后才切换到新语义，界面不能静默迁移。

### 7.2 分组详情

现有分组详情抽屉增加“路由能力”区域：

- 开启或关闭“从 default 自动适配”。
- 草稿和激活状态控制。
- 真人能力三态分段控件或选择器。
- 成本模式多选控件。
- 当前条件的预计匹配数量。
- 激活前校验结果。

没有匹配目标时允许保存草稿，但禁止激活。

### 7.3 适配目标目录

“查看目标”打开宽版目标目录，按规范模型、渠道和目标展示：

- 规范模型。
- 渠道名称和 ID。
- 上游模型。
- 成本变体。
- 真人能力。
- 当前生效成本模式。
- 匹配状态。
- 不匹配或排除原因。

支持按模型、渠道、成本模式和匹配状态筛选。目标状态至少包括：

- 已匹配。
- 真人能力不匹配。
- 真人能力未知。
- 成本模式不匹配。
- 成本规则缺失或无效。
- 已人工排除。
- 目标禁用。
- 渠道不可用。

目录展示静态适配结果。素材约束、实际时长和毛利门禁明确标注为请求时继续判断，不在目录中伪装成静态通过。

### 7.4 人工排除

- 管理员可以从已匹配目标执行排除。
- 管理员可以恢复已排除目标。
- 不兼容目标不提供“强制加入”。
- 失效排除项提供清理命令。
- 保存、激活、排除、恢复和清理操作写入管理审计日志。

## 8. 管理接口

新增面向管理端的动态预览能力，具体路由沿用项目现有权限和错误响应规范。

接口职责分为：

1. 读取分组档案摘要和适配计数。
2. 使用已保存档案分页查询适配目标。
3. 使用未保存表单值执行预览，支持管理员保存前验证。
4. 激活档案前执行同一套服务端校验。

预览和真实路由必须复用同一个静态能力解析器，禁止前端复制匹配逻辑。接口不返回渠道密钥、成本配置原始 JSON 或其他敏感字段。

## 9. 渠道模板导入

渠道模板继续权威管理：

- `default` 路由策略和目标。
- 渠道模型映射。
- 供应商成本规则。
- 模板明确声明的分组路由要求。

默认行为：

```text
sd收录表刷新
-> 更新 default 路由策略、目标和成本规则
-> 保留运营分组档案和人工排除
-> 动态重新计算适配结果
-> 生成新增、减少和失效警告
```

导入文档缺少 `group_routing_requirements` 节点时，继续表示本批次不修改现有分组档案。

模板显式携带对应节点时可以更新能力条件，但人工排除项默认不由模板覆盖。若未来需要模板权威管理排除项，必须使用独立显式字段和审阅提示，不能通过节点缺失推断删除。

导入校验需要支持新字段和旧 `require_real_person` 字段的兼容转换。发布或激活失败时，分组档案、来源策略、成本规则和渠道状态不得留下部分更新。

## 10. 错误与诊断

普通客户只接收稳定的通用错误，不暴露上游渠道、供应商成本或路由规则。

管理员诊断至少记录：

- 实际账号或 Token 分组。
- 档案状态和来源分组。
- 真人能力模式和请求级真人要求。
- 允许成本模式。
- 来源策略 ID。
- 匹配、人工排除和各类不匹配数量。
- 最终目标和成本规则快照。
- 严格成本及毛利门禁结果。

审计数据继续进入管理员可见日志字段，普通日志视图剥离内部诊断。

## 11. 性能和一致性

- 复用现有路由策略快照缓存，不复制每个运营分组的策略快照。
- 分组能力档案使用现有线程安全配置快照，保存成功后立即对后续请求生效。
- 真人能力和人工排除先在内存快照中筛选。
- 对剩余目标一次批量解析生效成本规则，禁止逐目标查询。
- 同一批成本规则同时服务于成本模式过滤和毛利门禁，避免重复读取。
- 适配目标目录使用服务端分页、稳定排序和批量查询。
- 所有数据库查询和迁移必须兼容 SQLite、MySQL 和 PostgreSQL。

## 12. 测试设计

### 12.1 配置测试

- 新旧字段兼容转换。
- 枚举、数组、重复值、未知字段和大小限制。
- 冲突的新旧真人配置拒绝保存。
- 草稿和激活状态转换。
- 激活时零匹配目标拒绝。

### 12.2 路由服务测试

- 未配置档案的旧分组行为不变。
- 真人三态与请求级要求的全部组合。
- 单个和多个成本模式匹配。
- 缺失、无效、退休和成本变体不一致规则。
- 人工排除和恢复。
- 来源策略新增、删除、禁用和目标变更后实时适配。
- 显式分组、自动分组、指定渠道、亲和和重试均不能绕过硬约束。
- 严格成本和毛利门禁继续使用完整供应商成本。

### 12.3 模型目录测试

- 只展示至少存在一个静态匹配目标的模型。
- 最后一个目标失效后模型消失。
- 目录结果与真实路由静态过滤结果一致。

### 12.4 导入测试

- 节点缺失时保留档案和排除项。
- 新旧字段导入。
- 模板更新 `default` 目标后适配结果变化。
- 重新导入后稳定排除继续生效。
- 已删除目标形成失效排除提示。
- 发布失败时事务回滚。

### 12.5 前端测试

- 编辑真人三态和成本模式多选。
- 草稿保存和激活校验。
- 适配数量预览。
- 目标目录筛选、分页和状态原因。
- 排除、恢复和清理失效排除。
- 加载、空状态、错误状态、键盘操作和可访问名称。
- `en`、`zh`、`zh-TW`、`fr`、`ja`、`ru`、`vi` 翻译完整。

### 12.6 E2E 验收

至少准备以下目标：

- 支持真人且按次计费。
- 支持真人且按时长计费。
- 不支持真人且按次计费。
- 真人能力未知或成本未知。

创建多个下游测试账号并分配不同分组，使用 Ark SDK 完成视频任务流程，核对：

- 模型目录。
- 路由目标。
- 任务和使用日志。
- 成本核算。
- 严格模式和毛利门禁。
- 管理员诊断与普通客户错误隔离。

## 13. 上线步骤

1. 部署兼容读取、匹配和管理端预览能力，不激活新档案。
2. 为运营分组创建草稿并核对适配目标目录。
3. 清理能力未知、成本未知和失效排除警告。
4. 使用内部测试账号激活一个 Canary 分组。
5. 运行 Ark SDK 真实用户完整流程，核对日志和成本。
6. 分批激活正式客户分组。
7. 输出分组、模型、目标、排除原因和真实请求结果的验收报告。

## 14. 非目标

- 不复制 `default` 路由策略为每个运营分组的独立策略。
- 不允许人工强制加入不满足能力条件的目标。
- 不替代上游内容安全审核。
- 不自动识别输入素材是否包含真人；请求级声明和目标能力元数据仍是路由事实来源。
- 不在静态适配目录中承诺请求级素材限制或毛利一定通过。
- 首版不支持从 `default` 以外的来源分组继承。

# 图像分辨率档位计费与渠道能力设计

## 1. 背景与目标

当前图像目录使用 `端点 + 具体 size + quality` 作为 SKU，例如
`gen-1024x1024-medium`。上游通常按 `1K/2K/4K` 与 `low/medium/high` 定价，
继续枚举具体宽高会增加全局售价、渠道成本和路由配置的维护量，也容易出现同一
档位重复或漏配。

本设计将图像计费和渠道能力统一为九宫格档位：
`1k/2k/4k × low/medium/high`。下游仍使用现有 OpenAI Images 请求格式，
可以传递上游接受的任意合法 `widthxheight`，系统不维护具体尺寸白名单，
也不改写原始尺寸后再转发。

## 2. 核心术语

- **分辨率档位**：由请求尺寸总像素数映射出的 `1k`、`2k` 或 `4k`。
- **能力组合**：一个分辨率档位与一个质量值的组合，例如 `2k × high`。
- **档位 SKU**：用于售价、成本和路由的稳定键，例如 `gen-2k-high` 或
  `edit-4k-low`。
- **具体尺寸**：请求中的原始 `size`，例如 `1536x1024`。它是上游协议字段，
  不是价格或渠道能力配置维度。

## 3. 分辨率档位规则

### 3.1 总像素阈值

按 `width × height` 的总像素数，从低到高匹配第一个满足上限的档位：

| 档位 | 总像素上限 | 数值 |
| --- | --- | ---: |
| `1k` | `1024 × 1024` | 1,048,576 |
| `2k` | `2048 × 2048` | 4,194,304 |
| `4k` | `2880 × 2880` | 8,294,400 |

边界值属于对应档位；超过 `8,294,400` 的请求没有可用档位，返回参数错误。
宽高比例和单边长度不参与档位判断。例如 `4096x1024` 的总像素数约为 4.19
百万，属于 `2k`；`3000x2000` 的总像素数约为 6 百万，属于 `4k`。

### 3.2 size 缺省与 auto

下游省略 `size`、传空值或传 `size=auto` 时统一归入 `1k`，并使用 `1k`
对应的售价、渠道能力和成本规则。透传给上游时保持现有请求构造逻辑；若上游
需要默认尺寸，则继续使用现有适配器默认行为，不把 `auto` 作为新的具体尺寸发送。

### 3.3 输入校验与安全

- 其他 `size` 值必须是正整数宽高组成的 `widthxheight` 格式。
- 解析和乘法必须在有界整数范围内完成，拒绝溢出、零值、负值和非数字输入。
- 不引入“公共模型尺寸白名单”或“渠道尺寸白名单”；合法尺寸是否最终被上游
  接受由上游协议响应决定。
- 对超过 4K 总像素的请求返回明确的客户端参数错误，不降级到 4K，也不把请求
  路由到其他档位。

## 4. SKU、售价与成本模型

### 4.1 新 SKU

生成端点使用 `gen-{tier}-{quality}`，编辑端点使用 `edit-{tier}-{quality}`。
`tier` 为 `1k`、`2k` 或 `4k`，`quality` 为 `low`、`medium` 或 `high`。
公共模型目录、全局用户售价、渠道成本变体和成本规则均引用同一档位 SKU。

下游请求的实际 `size` 只在运行时解析为 `tier`；原始 `size` 和 `quality` 继续
原样传给上游适配器（`size=auto` 按现有默认尺寸构造）。

### 4.2 渠道能力矩阵

每个图像渠道的日常配置只需要选择公共模型、填写上游模型映射，然后在九宫格中
勾选能力组合。勾选某格即启用对应档位和质量，并必须填写该格每张图片的供应商
成本；未勾选的格不生成或停用对应成本变体，不参与路由。

成本金额必须是有效的非负小数；勾选但缺少成本、格式非法或无法关联有效模型映射
时，保存被拒绝。系统自动生成 OpenAI Images 协议绑定和档位成本键，日常流程不
要求管理员编辑 JSON。

### 4.3 路由匹配

候选渠道必须同时满足公共模型、端点、运行时档位、质量、渠道已勾选能力和启用的
成本规则。`lowest_cost` 继续按当前成本规则排序；成本未知、成本规则不活跃或
毛利约束不满足的候选排除。渠道优先级和权重的既有语义保持不变。

没有精确能力组合时，不自动把请求降级或升级到其他档位；系统返回“该尺寸与质量
暂不可用”类错误。

## 5. 管理界面

### 5.1 全局图像售价

全局图像售价页面只展示 `1K/2K/4K × low/medium/high` 九宫格，支持表格内直接
编辑并保存。页面显示档位的总像素上限和当前生效状态，帮助管理员理解 `size`
如何归类，但不展示或要求维护具体尺寸列表。

### 5.2 渠道编辑

渠道编辑页提供与全局售价一致的能力矩阵。支持按行全选某一档位的三种质量，
也支持单格勾选；勾选后立即显示成本输入。协议配置默认填充系统内置的
OpenAI Images profile，保留高级 JSON 查看能力但不把它作为正常配置入口。

## 6. 旧数据迁移与兼容

### 6.1 映射规则

旧的具体尺寸 SKU 按其尺寸总像素数映射到新档位：

- 不超过 `1024 × 1024` 映射到 `1k`。
- 不超过 `2048 × 2048` 映射到 `2k`。
- 不超过 `2880 × 2880` 映射到 `4k`。
- 超出 4K 上限或无法解析的旧键不自动迁移，生成冲突/异常报告。

端点和质量保持不变。例如 `gen-1024x1024-medium` 映射为
`gen-1k-medium`。

### 6.2 冲突处理

同一渠道、同一上游模型、同一端点和档位出现多个旧成本且金额不一致时，不自动
选择或覆盖任何金额，迁移批次标记为冲突并阻止发布该档位，管理员解决后才能
激活。金额一致的重复旧规则可以合并为一条新档位规则。

迁移期间保留旧键的兼容读取，确保历史日志和已结算记录仍可查看；新请求统一
使用档位键。未完成迁移、缺成本或冲突的候选不参与新请求路由。

## 7. 错误处理与可观测性

- 非法 `size`、整数溢出或超过 4K 总像素：返回 400 类参数错误，并记录结构化
  原因，不能进入计费或渠道选择。
- 没有对应能力组合、成本规则缺失或候选被成本策略排除：返回现有路由不可用
  错误，日志包含公共模型、端点、档位、质量和排除原因。
- 迁移冲突报告至少包含渠道、上游模型、端点、目标档位、旧 SKU 和冲突金额。

## 8. 测试与验收

### 后端

- 覆盖缺省 `size`、空值和 `auto` 归入 `1k`。
- 覆盖三个阈值的边界、典型矩形尺寸、超出 4K、非法格式、零值和乘法溢出。
- 验证同一 `size + quality` 只生成对应档位 SKU，并使用一致的售价、渠道能力和
  成本规则。
- 验证未勾选能力、缺成本、非活跃成本规则和成本策略排除时不会路由。
- 验证旧 SKU 自动映射、一致成本合并、不一致成本冲突阻止发布，以及历史旧键
  兼容读取。
- 回归 OpenAI Images 生成和编辑端点，确认原始尺寸仍按现有适配器逻辑透传。

### 前端

- 九宫格直接编辑、勾选即显示成本、缺成本阻止保存、保存成功和失败状态。
- 页面不出现具体尺寸白名单配置入口；非图像渠道不显示图像能力矩阵。
- 执行受影响测试、TypeScript 类型检查、lint 和生产构建。

### 容器验收

在本机 compose 容器中完成管理页面浏览器验收，并使用测试 API Key 发起缺省
`size`、`auto`、1K/2K/4K 边界和多渠道路由请求，核对响应、用量日志、用户售价、
供应商成本和实际渠道选择。

## 9. 非目标

- 不为每个具体宽高创建长期 SKU。
- 不维护公共模型或渠道的具体尺寸白名单。
- 不自动把不匹配的请求降级到其他分辨率档位。
- 不改变非图像渠道、既有非图像计费和现有渠道优先级/权重语义。

# 成本核算模式悬停说明设计

## 背景与目标

成本核算页面右上角使用 `Disabled`、`Tracking`、`Strict` 三个按钮切换运行模式。当前按钮只显示模式名称，管理员无法在切换前直接判断各模式是否记录供应商成本、是否启用利润门禁，以及是否影响用户侧原有计费。

本次优化为三个模式按钮分别增加悬停说明，让管理员无需离开当前页面即可理解模式差异。修改仅涉及说明交互，不改变模式切换、权限校验、成本覆盖校验或后端设置接口。

## 方案选择

采用按钮级独立 Tooltip，每个按钮对应自己的说明。相较于整组按钮共用一个帮助入口，独立 Tooltip 能直接建立模式与行为之间的对应关系；相较于常驻说明，Tooltip 不会挤占页面右上角的紧凑操作空间。

Tooltip 使用项目现有 Base UI 封装，不新增依赖。说明在鼠标悬停和键盘聚焦时显示，并置于按钮下方。`Strict` 因成本覆盖不完整而禁用时，鼠标悬停仍应能够显示说明。

## 文案设计

- `Disabled`：关闭供应商成本核算和利润门禁，用户原有计费继续运行。
- `Tracking`：记录收入、供应商成本、利润和异常，但不拦截成本缺失或低于最低毛利要求的路由。
- `Strict`：记录成本，并拦截成本未知、规则缺失或预计毛利低于最低要求的路由；启用前需要完整成本覆盖。

所有新增文案通过 `t(...)` 使用，并补齐 `en`、`zh`、`zh-TW`、`fr`、`ja`、`ru`、`vi` 七个语言文件。语言文件仅通过项目规定的脚本写入，完成后运行 i18n 同步工具。

## 组件与交互

在成本核算页面的模式 `ToggleGroup` 外提供统一的 `TooltipProvider`，三个 `ToggleGroupItem` 分别关联一个 `Tooltip`。Tooltip 内容限制最大宽度并允许自然换行，避免长语言文案撑出视口。

模式按钮继续保持现有受控选择逻辑：

1. 点击可用模式后调用现有设置更新接口。
2. 覆盖不完整时，`Strict` 保持禁用，不绕过现有门禁。
3. 设置请求进行中或加载中时，整组按钮保持禁用。
4. Tooltip 不触发模式切换，也不修改当前模式状态。

## 可访问性

Tooltip 同时支持悬停和键盘聚焦。按钮保留现有可访问名称，说明作为补充信息，不替代按钮文字。禁用按钮的悬停触发层不改变按钮的禁用语义，也不进入模式选择流程。

## 测试与验收

新增成本核算模式控件的交互回归测试，至少覆盖：

- 三个模式按钮均存在对应说明。
- 悬停按钮后显示正确说明。
- 键盘聚焦可用按钮后显示说明。
- `Strict` 禁用时仍可通过悬停查看说明，且不能触发模式切换。

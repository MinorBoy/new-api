# 分组列表生命周期管理设计

## 背景

“系统设置 → 分组定价”已经能够维护分组倍率、充值倍率、用户可选状态、描述和动态路由能力画像，但分组目前只有“存在”与“删除”两种状态。上线运营需要临时停止某个客户能力分组，同时保留其定价和路由配置，以便后续恢复；删除操作也缺少不可误触的二次确认。

## 目标

- 分组列表新增明确的启用/停用状态，新建分组默认启用。
- 停用分组时保留全部配置，但禁止其继续承担用户分配、令牌选组和请求路由。
- 删除分组必须经过确认弹窗，并清理该分组拥有的关联配置。
- 兼容既有安装：未配置状态的已有分组按启用处理。

## 非目标

- 不自动迁移处于停用分组的用户。
- 不在本期提供批量启停、定时启停或状态审计历史。
- 不改变分组倍率、充值倍率或能力画像的业务含义。

## 配置模型

在 `group_ratio_setting` 中增加 `group_status` 映射，结构为 `map[string]bool`，键为分组名，值表示是否启用。该映射沿用现有系统设置持久化机制，不新增业务数据库表。

状态解析遵循向后兼容规则：

1. 映射中明确为 `false` 的分组视为停用。
2. 映射中明确为 `true` 的分组视为启用。
3. 映射中没有记录的既有分组默认启用。
4. 新建分组时显式写入 `true`，避免状态依赖隐式默认值。

后端提供集中读取方法，例如 `IsGroupEnabled(name)`，业务调用方不得各自解析映射。配置更新必须校验状态映射键名非空；状态映射出现不属于分组注册表的孤立键时拒绝保存，并沿用现有设置校验的错误返回方式。

## 运行时语义

停用是可恢复的运营控制，不等同于删除：

- 保留分组倍率、充值倍率、用户可选描述、用户组倍率覆盖、能力画像和路由排除项。
- 分组不再出现在可分配、可选或公开定价的可用分组列表中。
- 新建或编辑用户、令牌时，后端拒绝分配停用分组，不能只依赖前端过滤。
- 已属于停用分组的用户不会自动迁移；其请求在进入渠道选择和计费前被拒绝，并返回可识别的“分组已停用”错误，避免落入默认路由或产生费用。
- 管理员将用户切换到启用分组，或重新启用原分组后，请求恢复。

`default` 分组允许停用，以保留运营自由度；界面在执行该操作前显示高风险说明。后端仍按同一规则拦截，不对 `default` 做隐式回退。

## 页面交互

### 状态列

分组表新增“状态”列，使用带可访问名称的 `Switch`：

- 开启表示启用，关闭表示停用。
- 切换普通分组立即更新当前表单状态，最终仍由页面现有“保存分组倍率”动作统一持久化。
- 停用 `default` 时弹出风险确认；取消后开关保持开启。
- 禁用态沿用页面现有 `disabled` 属性，保存期间不可重复操作。
- 桌面端显示独立列；移动端沿用表格响应式布局，确保开关和操作按钮不会重叠或产生横向溢出。

### 删除确认

点击删除图标只打开确认弹窗，不立即修改数据。弹窗包含：

- 标题“删除分组”；
- 待删除分组名；
- 将同时删除定价、可选描述、状态、用户组倍率覆盖和动态路由能力配置的说明；
- “取消”和破坏性样式的“确认删除”操作。

确认后在一次前端状态变更中移除该分组在以下配置中的数据：`GroupRatio`、`TopupGroupRatio`、`UserUsableGroups`、`GroupGroupRatio`、`GroupSpecialUsableGroup`、`GroupRoutingRequirements` 和 `group_status`。取消或关闭弹窗不产生任何修改。删除不自动修改现有用户；保存时若后端检测到仍有用户引用该分组，应拒绝删除并提示管理员先迁移用户，防止生成悬空账号状态。

## 数据流

1. 页面加载分组相关设置，并将缺失的状态按启用呈现。
2. 新建分组同时生成默认倍率和显式启用状态。
3. 用户切换状态或确认删除后，编辑器更新各 JSON 设置字段。
4. 现有保存入口一次提交所有变更；任一字段校验失败时整体显示错误，不把页面呈现为已保存。
5. 后端更新内存设置后，可用分组查询、用户/令牌分配校验和请求入口统一读取集中状态。

## 错误处理

- 状态 JSON 非法、键名为空或值类型错误时拒绝保存。
- 删除仍被用户引用的分组时返回明确业务错误，原配置保持不变。
- 请求使用停用分组时，在真实上游调用和计费预扣前失败。
- 切换或删除尚未保存时沿用现有表单脏状态，不显示成功提示。

## 测试与验收

后端测试覆盖：

- 旧配置缺少状态时默认启用。
- 显式停用和重新启用的解析结果。
- 停用分组从可用列表中排除。
- 用户与令牌不能新分配到停用分组。
- 已有停用分组用户的请求在计费和渠道调用前失败。
- 仍被用户引用的分组不能删除。

前端测试覆盖：

- 新建分组默认开关开启并序列化为 `true`。
- 普通分组启停更新状态字段，其他配置保持不变。
- 停用 `default` 必须确认，取消不改变状态。
- 点击删除不立即删除；取消保留；确认后清理全部关联配置。
- 所有新增文案在七种语言中存在。

浏览器验收覆盖桌面与 `390 × 844` 移动视口，验证开关、删除确认、键盘焦点恢复、保存后刷新持久化以及无横向溢出。最后使用停用测试分组发起低成本请求，确认请求在真实上游调用前被阻断，再恢复该分组并验证正常路由。

## 兼容性与风险

- 缺失状态默认启用，升级不会意外停用生产分组。
- 状态键以分组名关联；重命名应视为旧分组删除和新分组创建，关联配置由编辑器同步迁移或清理，不能留下旧键。
- 分组配置分散在多个 JSON 设置中，保存和删除必须采用后端一致性校验，避免只更新其中一部分。
- 请求入口拦截是安全边界；前端隐藏和列表过滤只用于改善体验，不能替代后端校验。

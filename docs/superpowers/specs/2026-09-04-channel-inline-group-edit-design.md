# 渠道列表内联分组编辑设计

## 目标

在渠道列表的“分组”列直接编辑渠道可访问的用户组。点击单元格后打开多选下拉，选择变化立即保存，减少进入渠道编辑抽屉的操作和误填概率。

## 交互

- 下拉选项来自现有用户组接口 `getGroups`。
- 当前渠道已配置的分组全部显示为已选；保留不在选项列表中的历史值，避免编辑时意外丢失。
- 支持单选和多选，至少保留一个分组；空选择不提交。
- 保存过程中控件禁用并显示轻量加载状态，避免并发覆盖。
- 保存成功后使渠道列表查询失效，展示新的分组徽章；失败时恢复原值并显示错误提示。
- 标签聚合行不提供该编辑控件，继续使用现有标签批量操作。

## 数据流

前端将选中分组数组用现有 `formatGroups` 转为逗号分隔字符串，调用 `updateChannel(id, { group })`。后端现有 `UpdateChannel` 负责校验、保存和能力刷新，无需新增 API 或数据库字段。

## 测试

- 选择一个分组后发送对应字符串并刷新列表。
- 选择多个分组时发送稳定的逗号分隔值。
- 保存失败时回滚到原分组并提示错误。
- 聚合行不触发更新。

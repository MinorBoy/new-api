# 渠道配置 JSON 导入

渠道配置导入将渠道、模型映射、成本规则、售价和模型路由分成两个边界明确的阶段：浏览器离线转换 Excel，管理端只接收经过规范化的 JSON 文档。Excel 文件和渠道凭据不会上传到导入 API，也不会写入导入批次、问题、报告或审计记录。

## 导入流程

1. 打开静态转换器，选择 V1 修正版工作簿或 V2 模板。转换器仅在本地浏览器处理文件，生成可下载的规范 JSON 和问题报告。
2. 在管理端的“渠道配置导入”页面上传 JSON。重复上传内容相同的文档会返回原有批次，不会创建重复批次。
3. 在现有渠道管理页面为每条渠道线路创建或选择渠道，填写渠道地址和凭据，并保持渠道禁用。导入页面只保存已确认的渠道 ID 和确认人，不读取或保存凭据。
4. 在导入向导中将每条逻辑线路绑定到已确认的渠道。可以跳过不需要导入的线路；所有依赖该线路的提案会被排除。
5. 处理未解决变体。例如 `CH-MEGABYAI/videos-standard` 必须先确认对应的渠道线路或明确排除，不能在身份不明时发布。
6. 执行暂存。系统重新校验文档、绑定、成本变体、售价、映射和路由，并生成可审阅的差异；暂存成本规则仍是草稿，不影响运行中的配置。
7. 审阅定价和路由差异，确认发布。发布事务按成本规则、售价、模型映射、路由定义和已审阅启用状态的顺序写入。

新建渠道、路由策略和路由目标在导入后始终保持禁用。请在发布后通过各自的管理页面完成实际联调和启用决策。

## 失败与恢复

| 状态或问题 | 含义 | 处理方式 |
| --- | --- | --- |
| `blocked` | JSON、绑定或冲突校验未通过 | 修正 JSON、绑定或冲突处理，然后重新上传或重新暂存。 |
| `staged` | 已生成草稿和差异，尚未通过发布前校验 | 补齐线路确认、解决问题后再次暂存。 |
| `ready` | 可以发布 | 审阅差异并确认发布。 |
| `STALE_BASE_VERSION` | 暂存后，受影响的现有活动配置已经变化 | 重新暂存，审阅更新后的差异，再发布。 |
| `publish_failed` | 发布事务没有完成，活动配置已回滚 | 查看脱敏失败原因，修正后执行校验/暂存，再次发布；不要重建渠道或草稿。 |
| `CACHE_REFRESH_PENDING` | 数据库已发布，但内存缓存刷新未完成 | 使用校验/重试缓存刷新；该操作不重新执行发布事务。 |
| `published` | 发布已完成 | 批次为只读记录；不能再次发布。 |

## 回滚原则

任何成本、定价、映射或路由写入失败都会使发布事务整体回滚，避免出现部分生效。已经成功发布的批次不执行隐式回滚；需要撤销时，使用新的 JSON 批次提交所需的修正配置，并再次审阅差异。

## 安全与审计

- 仅上传 JSON，禁止上传 Excel、压缩包或渠道凭据。
- 导入文档、批次项目、问题、审计和日志均进行敏感字段检查；检测到凭据形式字段会拒绝导入。
- 每个批次通过内容 SHA-256、实体业务 ID 和实体哈希实现幂等与可追溯。
- 路由目标固定关联 `cost_variant_key`；严格成本覆盖不会回退到另一成本变体。
- 发布前后基线与发布审计用于识别并阻止过期的暂存计划。

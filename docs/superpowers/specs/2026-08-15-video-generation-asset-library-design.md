# 视频生成页使用素材库设计

**日期：** 2026-08-15
**状态：** 已确认方案，待实施

## 目标

在 `/video-generation` 的参考图片区域增加“公网 URL / 素材库”两种互斥模式。用户可以从自己的
角色素材库中多选 `Active` 图片素材，页面把本项目素材 ID 转换为 Ark SDK 标准的
`asset://<ASSET_ID>` 引用并提交到现有视频任务接口。

本次同时让视频页的普通参考媒体数量随 Seedance 模型系列变化：Seedance 2.0 使用
`9/3/3` 的图片、视频、音频上限，Seedance 2.5 使用 `30/10/10`。角色素材当前仍只支持
映射到 Secure `video-2.0-pro` 的基础版 Seedance 2.0，最多 9 个，不因 Seedance 2.5 普通参考
图片上限扩大而放宽。

## 已确认范围

- 素材选择器只选择已有素材，不在视频页内创建素材。
- 选择器提供“前往素材库创建”入口，创建仍由 `/assets` 页面负责。
- 展示用户全部素材状态，只有 `Active` 素材可以选择。
- 支持多选、取消选择和跨分页保留选择顺序。
- 素材模式和普通图片 URL 模式互斥。
- 素材模式保留参考音频，但清空并禁用普通图片 URL 和参考视频。
- 不执行真实付费视频生成作为本次默认验收步骤。

## 不在本次范围

- 不在视频页内创建、刷新单个或删除素材。
- 不给 Seedance 2.5 或非 Secure 渠道增加角色素材复制、迁移或自动重建能力。
- 不修改素材与创建用户、Secure 渠道及上游 API Key 的既有绑定规则。
- 不增加新的素材类型；素材库仍只包含图片角色素材。
- 不在前端推断或展示素材绑定的上游渠道凭据。

## 方案选择

### 方案 A：参考图片区域内切换（选用）

在现有“参考图片”编辑器顶部增加分段控件。公网 URL 模式保留逐行 URL 输入；素材库模式在同一区域
展示分页缩略图网格、状态、选中数量和素材库入口。模式关系直接可见，用户无需离开表单或理解两套
图片来源能否混用。

### 方案 B：弹窗选择（未选用）

主表单只显示“从素材库选择”按钮，在弹窗内浏览和多选。它能容纳更多素材，但会把互斥模式和当前
选择隐藏在第二层界面中，首版交互成本较高。

### 方案 C：独立并列面板（未选用）

公网参考和素材库同时展示，选择一侧后禁用另一侧。信息完整但占用空间大，在当前三类参考媒体布局
中容易造成视觉拥挤。

## 组件与状态设计

### 表单状态

`VideoGenerationForm` 增加两个独立字段：

- `imageSource: 'url' | 'asset'`：当前参考图片来源。
- `assetIds: string[]`：按用户选择顺序保存本项目素材 ID。

素材 ID 不写入 `media.images`，避免 `asset://` 引用被现有 HTTP(S) URL 校验误判，也避免普通 URL
和角色素材在状态层混合。表单重置恢复现有示例的公网 URL 模式，并清空 `assetIds`。

### 组件边界

- `ReferenceMediaEditor` 继续负责普通图片、视频和音频 URL 输入，数量上限改为显式 `limit` 参数。
- 新增 `AssetPicker`，负责分页加载素材、状态展示、多选、选中计数、空状态、错误重试和素材库入口。
- 参考图片区域负责渲染分段控件，并根据 `imageSource` 在 URL 编辑器和 `AssetPicker` 之间切换。
- `lib/request.ts` 负责模型系列能力解析、媒体限制和 Ark 请求组装，不在 React 组件中重复模型名判断。

`AssetPicker` 复用 `GET /api/v3/assets?type=image&page=<n>&page_size=<n>`。分页控件使用接口返回的
`total`、`page` 和 `page_size`，跨页选择由表单中的 `assetIds` 保持。打开选择器和手动刷新时重新获取
列表；不在后台持续轮询。

## 模型能力与数量限制

页面根据当前选择的逻辑模型名称识别 Seedance 系列。识别时忽略大小写及 `-`、`_`、`.`、空格等
分隔符，并兼容公开规范名和现有上游别名。

| 模型系列 | 普通参考图片 | 参考视频 | 参考音频 | 角色素材 |
|---|---:|---:|---:|---:|
| Seedance 2.0 | 9 | 3 | 3 | 最多 9 个 |
| Seedance 2.0 Fast、2.0 Mini | 9 | 3 | 3 | 不支持 |
| Seedance 2.5 | 30 | 10 | 10 | 不支持 |
| 其他或无法识别 | 9 | 3 | 3 | 不支持 |

模型改变后，三个 URL 编辑器的计数和新增按钮上限立即更新。若用户已填写的 URL 数量超过新模型
上限，页面保留原输入、禁用提交并展示对应字段错误，不静默删除用户数据。

角色素材只在已识别的基础版 Seedance 2.0 显示为可用模式；Fast 和 Mini 不开放。若用户在素材模式
下切换到 Seedance 2.5、Fast、Mini 或未知模型，页面清空 `assetIds`，切回公网 URL 模式，并提示
当前模型不支持角色素材。

## 交互规则

### 切换到素材库

切换后立即清空 `media.images` 和 `media.videos`，保留 `media.audios`。分段控件、素材计数和已选状态
保持在参考图片区域内，不额外打开弹窗。

素材卡片显示缩略图、素材 ID 和状态。`Active` 卡片支持鼠标、触摸和键盘选择；其他状态显示状态
标签并设置禁用语义。达到 9 个后，未选择的可用卡片进入禁用状态，已选择卡片仍可取消。

### 切回公网 URL

切换后立即清空 `assetIds`，恢复普通图片 URL 编辑器。参考视频不会自动恢复此前被清空的内容。

### 空状态与失败状态

- 没有素材时展示空状态和“前往素材库创建”入口。
- 素材列表加载失败时保留明确错误和重试按钮，不把失败误展示为空列表。
- 素材图片加载失败时使用稳定占位，不影响选择、状态和素材 ID 展示。
- 服务端返回素材不存在、非 `Active`、跨渠道或渠道不可用时，沿用现有视频任务错误提示链路。

## 请求与后端数据流

`buildVideoRequest()` 在公网 URL 模式下保持现有行为。在素材模式下，它按 `assetIds` 顺序生成：

```json
{
  "type": "image_url",
  "role": "reference_image",
  "image_url": {
    "url": "asset://asset-20260401123823-6d4x2"
  }
}
```

请求继续提交到 `POST /api/v3/contents/generations/tasks`。既有视频素材路由中间件负责校验用户归属、
素材状态、数量和单一绑定渠道，将本项目素材 ID 映射为上游 `asset-local-*`，并强制使用素材创建时
绑定的 Secure 渠道/API Key。

中间件当前只接受旧格式 `asset-<32位十六进制>`，与已经启用的新格式
`asset-YYYYMMDDhhmmss-<5位小写字母数字>` 不一致。本次将校验改为同时接受两种已生成格式，保证
新素材可用于视频，同时不破坏数据库中的旧素材引用。角色素材的服务端上限仍为 9，不扩展到 30。

## 校验与错误处理

- Schema 根据 `model` 动态校验三个普通媒体数组的数量。
- 公网 URL 模式继续要求非空项为 HTTP(S) URL。
- 素材模式要求 `assetIds` 非空项为本项目公开素材 ID，并限制最多 9 个。
- prompt、普通参考媒体和角色素材三者至少有一项有效输入。
- 请求组装只使用当前 `imageSource` 对应的数据，防止陈旧隐藏状态进入请求。
- 后端继续作为素材归属、状态、渠道一致性和上游能力的最终权威。

所有新增可见文案使用 `t('English source key')`，同步到 `en`、`zh`、`zh-TW`、`fr`、`ja`、`ru`、
`vi` 七个 locale。

## 测试与验收

### 前端单元与组件测试

- 模型系列识别及 `9/3/3`、`30/10/10`、未知模型回退限制。
- 公网 URL 和角色素材请求组装，包含多素材顺序和互斥保证。
- 模式切换时清空冲突字段、保留音频及表单重置行为。
- 基础版 Seedance 2.0 可使用素材模式，Fast、Mini、Seedance 2.5 和未知模型不可使用。
- `Active` 可选，其他状态禁用；选择、取消、跨页保留和 9 个上限。
- 加载、空列表、请求失败、重试及图片失败占位。
- URL 数量超过切换后模型限制时保留输入并阻止提交。

### 后端回归测试

- 新旧两种公开素材 ID 都能被视频素材中间件解析。
- 畸形素材 ID、重复引用、普通图片混用及超过 9 个角色素材继续被拒绝。
- 既有用户归属、`Active` 状态和单一渠道绑定测试保持通过。

### 工程与浏览器验收

运行受影响 Vitest、Go 测试、前端 typecheck、涉及文件 lint、生产构建和 `git diff --check`。使用浏览器
在桌面和移动端验证模式切换、分页素材选择、禁用状态、计数、错误状态、请求 JSON 以及无重叠布局。
请求预览必须显示 `asset://asset-*`，且素材模式下不得包含普通图片 URL 或参考视频。

本次默认不提交真实付费视频任务。若另行要求真实链路验收，应使用可计费测试账号，并单独记录任务
ID、绑定渠道、上游状态、视频 URL 和账务结果。

## 风险与兼容性

- 素材可能在加载后失效或被上游标记为失败；提交时仍必须由后端重新校验。
- 同一用户的素材可能绑定到不同 Secure 渠道；前端不暴露渠道凭据，跨渠道选择由后端返回冲突。
- Seedance 2.5 的普通媒体上限扩大后会产生更长表单；编辑器必须保持稳定滚动和移动端宽度，不能因
  30 个输入项挤压请求预览或其他媒体区域。
- 新旧素材 ID 双格式兼容只用于读取和引用；新建素材继续只生成可读时间戳格式。

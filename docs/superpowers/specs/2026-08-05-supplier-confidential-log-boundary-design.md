# 供应商敏感信息日志边界设计

## 背景

使用日志和任务日志已经按账号角色区分数据范围：普通用户读取自己的日志和任务，管理员读取全量记录，成本核算接口额外要求 `CostAccountingRead`。但是普通用户接口仍复用内部数据库模型或管理员 DTO，只在部分字段上做删除或依赖前端条件渲染。

这种实现不能满足供应商信息绝对保密要求。普通用户仍可能从 API 响应、浏览器开发者工具、原始任务结果 URL 或新增但未被排除的字段中获得渠道 ID、上游请求 ID、上游模型、成本和价格等信息。

## 权限边界

- 普通终端用户只能查看自己的用户侧请求、消耗、任务状态和最终结果。
- 管理员通过管理员日志接口查看完整日志和任务审计。
- 供应商成本核算、尝试时间线和审计历史只允许管理员且具备 `CostAccountingRead` 权限时读取。
- 普通用户接口无论由普通账号还是管理员账号调用，都只返回公开 DTO。管理员需要完整审计时必须调用管理员接口。
- 前端显示条件不是安全边界；后端响应必须在序列化前完成数据隔离。

## 保护范围

以下内容属于供应商敏感信息，不得出现在普通用户 API 响应、页面、复制内容、下载内容或错误消息中：

- 渠道 ID、渠道名称、渠道类型和供应商平台。
- 渠道 Base URL、API Key、代理地址和其他认证信息。
- 上游请求 ID、上游任务 ID 和上游原始请求、响应。
- 上游模型 ID、模型映射、候选模型和路由目标。
- 供应商成本、合同单价、标准化美元成本、成本规则、规则版本和成本变体。
- 路由尝试、重试链、获胜尝试、失败尝试和渠道亲和信息。
- 成本核算请求、计量事实、对账状态、审计历史和利润数据。
- 可用于反推以上信息的内部倍率、价格表达式、分组、计费路径和路由元数据。
- 直接暴露供应商域名或对象存储域名的任务结果 URL。

用户最终支付金额、用户侧消耗量和用户请求的公共模型 ID 不属于供应商敏感信息，可以通过公开 DTO 返回。公开响应不得返回供应商成本或用于计算供应商成本的单位价格和倍率。

## 方案选择

### 方案 A：公开 DTO 白名单

采用。普通用户日志和任务日志使用独立的、编译期明确字段的公开 DTO。管理员接口继续使用完整审计 DTO。原始 `map`、数据库模型和管理员 DTO 不得直接作为普通用户响应。

该方案默认拒绝未知字段：以后新增内部字段时，不会自动进入普通用户响应。

### 方案 B：在现有模型上删除敏感字段

不采用。删除列表需要持续追踪所有新增字段，容易因漏删产生回归。现有 `formatUserLogs` 只删除少数键，已经证明该方案不能形成稳定保密边界。

### 方案 C：只修改前端显示

不采用。前端隐藏无法阻止用户查看网络响应或直接调用 API。

## 后端设计

### 使用日志公开 DTO

`/api/log/self` 和 `/api/log/token` 返回公开使用日志 DTO，只允许以下类别的字段：

- 公开日志标识和创建时间。
- 日志类型、已脱敏的用户侧状态或说明。
- 用户自己的 Token 名称。
- 用户请求的公共模型 ID。
- 用户最终消耗额度、输入 Token、输出 Token、响应时间和流式标志。
- new-api 请求 ID。
- 明确列入白名单的用户侧计量、订阅消耗和登录审计字段。

公开 DTO 不包含 `channel`、`channel_name`、`group`、`ip`、`upstream_request_id`。普通用户也不接收通用的 `other` 原始对象；后端把允许公开的用户侧事实映射到专用公开结构，未知键一律丢弃。

用户侧计费只展示最终消耗，不返回 `model_price`、`duration_price`、`model_ratio`、`group_ratio`、价格表达式、匹配阶梯、上游计费来源或供应商成本核算引用。

普通用户使用日志列表、统计和模型筛选接口不接受 `channel`、`group` 或 `upstream_request_id` 过滤条件，避免通过响应数量或命中状态探测内部值。允许的筛选项限于时间、日志类型、用户自己的 Token、公共模型和 new-api 请求 ID。

`/api/log/` 管理员接口保持完整日志响应，不改变内部审计数据。

### 任务日志公开 DTO

`/api/task/self` 返回独立的公开任务 DTO，只包含：

- 公共任务 ID。
- 创建、提交、开始、完成和更新时间。
- 用户请求的公共模型 ID 和公开操作类型。
- 状态、进度、失败原因。
- 用户最终消耗额度。
- 规范化后的最终用户响应。

公开任务 DTO 不包含数据库内部 ID、用户 ID、渠道 ID、供应商平台、内部分组、请求路径、原始 `Properties`、原始 `Data`、原始用户请求、上游响应、路由对象、上游任务 ID 和计费上下文。

普通用户任务列表和筛选项接口不接受渠道 ID、供应商平台、内部分组或用户 ID 条件。允许的筛选项限于时间、公共任务 ID、公共模型、公开操作类型和任务状态。

最终用户响应继续遵守现有 Seedance 终态响应合同，但在进入公开 DTO 前执行公开投影：

- `id` 固定为 new-api 公共任务 ID。
- `model` 固定为用户请求的公共模型 ID。
- `status`、`usage`、时间和生成参数使用已规范化的用户侧事实。
- `content.video_url` 固定使用 `taskcommon.BuildProxyURL` 生成的 new-api 视频代理地址。
- 不允许回退到原始供应商视频 URL。无法生成代理地址时省略结果 URL并在服务端记录不含秘密值的告警。
- 失败响应保留已脱敏错误，不包含上游错误正文或供应商标识。

`/api/task/` 管理员接口继续返回完整任务审计 DTO，包括现有上游响应和最终用户响应。

本设计更新了 `2026-08-04-cost-profit-colors-and-task-result-audit-design.md` 中“最终用户响应仅管理员可见”的旧约束：任务所有者可以查看公开投影后的最终用户响应，但不能查看上游响应。

### 成本核算

成本核算接口继续使用 `AdminAuth` 和专用权限：

- `CostAccountingRead`：读取供应商成本规则、请求详情、尝试、审计和利润报告。
- `CostAccountingWrite`：维护成本规则。
- `CostAccountingReconcile`：执行对账。

普通用户日志响应不返回 `cost_accounting_request_id`，因此不能从日志详情发现或拼接成本核算请求。即使直接请求成本核算接口，后端权限仍返回拒绝响应。

### JSON 和错误处理

- 原始 JSON 的解析与生成使用项目 `common` JSON 包装函数。
- 公开投影只读取已定义的用户侧字段，不透传未知 JSON。
- 转换失败时返回最小公开信息或省略可选字段，不把原始 JSON、URL、密钥或上游错误放入用户错误消息。
- 服务端告警只记录公共请求 ID 和错误类别；需要管理员排查的完整事实保留在数据库审计中。

## 前端设计

### 使用日志

普通用户详情只展示请求 ID、Token、公共模型、用户侧用量、响应时间和最终消耗。以下区域只在管理员全量视图中存在：

- 渠道和重试链。
- 上游请求 ID。
- 模型映射和上游模型。
- 供应商成本核算。
- 尝试时间线。
- 对账审计历史。
- 供应商价格、成本和计费路径。

普通用户不显示 `sensitiveVisible` 控件。该控件仅用于管理员在页面上临时遮罩已经有权查看的数据，不能改变 API 权限。

### 任务日志

普通用户任务列表和详情展示公共任务事实及最终用户响应。管理员全量视图继续展示渠道、用户、上游创建响应、轮询数据和任务审计信息。

前端类型区分公开日志和管理员日志，普通用户组件不声明或消费管理员敏感字段。即使异常测试数据携带敏感字段，普通用户组件也不能渲染对应入口和内容。

## 数据流

```text
数据库完整日志、任务和成本账本
        |
        +--> 管理员日志接口
        |      +--> AdminAuth
        |      +--> 完整审计 DTO
        |
        +--> 成本核算接口
        |      +--> AdminAuth + CostAccountingRead
        |      +--> 成本、尝试和审计 DTO
        |
        +--> 普通用户 self/token 接口
               +--> 账号或 Token 所有权过滤
               +--> 公开 DTO 白名单投影
               +--> 用户侧页面和 API 响应
```

## 数据与兼容性

- 不修改数据库结构，不删除内部日志、任务私有数据或成本账本。
- 继续兼容 SQLite、MySQL 和 PostgreSQL。
- 管理员接口保持现有完整能力。
- 项目尚未上线，普通用户响应直接替换为安全合同，不为旧敏感字段保留兼容输出。
- 历史任务如果保存了原始供应商 URL，公开 DTO 仍只生成 new-api 代理 URL。
- 公共模型边界继续沿用现有规则；这里只处理日志和任务输出，不改变模型路由、售价或供应商成本结算。

## 测试策略

### 后端合同测试

固定测试数据同时写入渠道名称、Base URL、API Key、上游模型 ID、上游请求 ID、供应商视频 URL、成本、价格、规则、尝试和审计。

对以下普通接口的完整序列化 JSON 做递归扫描：

- `GET /api/log/self`
- `GET /api/log/token`
- `GET /api/task/self`

断言敏感字段名和敏感测试值均不存在，同时断言用户侧请求 ID、公共模型、最终消耗、任务状态和最终用户响应仍然存在。任务成功响应中的视频 URL 必须是 new-api 代理地址。

查询边界测试还要证明普通用户提交渠道、平台、分组或上游请求 ID 条件时不会形成内部数据探测能力；普通筛选项接口不得返回这些维度。

管理员合同测试断言 `GET /api/log/`、`GET /api/task/` 和成本核算详情仍返回完整审计事实。权限测试断言普通用户不能访问管理员日志、管理员任务或成本核算接口。

### 前端回归测试

- 普通用户详情中不存在供应商成本核算、尝试时间线、审计历史、渠道、重试链、上游请求 ID、上游模型和上游响应。
- 普通用户仍可查看最终消耗和任务最终用户响应。
- 管理员全量视图继续显示完整审计区域。
- 向普通用户组件注入带敏感字段的异常对象时，页面仍不渲染敏感信息。

### E2E 验收

使用普通用户和管理员账号分别验证使用日志、任务日志和成本核算：

- 检查桌面和移动端页面。
- 检查浏览器网络响应。
- 直接调用普通和管理员 API 并扫描 JSON。
- 验证任务视频地址只使用 new-api 代理域名。
- 验证管理员成本、价格、尝试和审计数据保持完整。

验收完成后生成简体中文报告，记录账号角色、接口矩阵、敏感字段扫描结果、任务响应结构和管理员审计保留情况。

## 验收标准

- 普通用户无法从页面、网络响应、直接 API、任务结果 URL 或错误消息获得任何供应商敏感信息。
- 普通用户使用日志和任务日志仍能完成用户侧查询、消费核对和结果查看。
- 管理员全量日志和具备 `CostAccountingRead` 权限的成本详情保持完整。
- 新增字段默认不会进入普通用户响应。
- 后端合同测试、前端回归测试、类型检查、Lint、构建和双角色 E2E 全部通过。

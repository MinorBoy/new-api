## 浏览器现场缺陷

### `issues` 返回 `null`

有命中目标时，后端将空问题集合序列化为 `null`，前端 Zod 合同要求数组，导致页面显示“路由预览不可用”。现已保证空集合返回 `[]`，并增加控制器回归测试。

### 重复业务键导致 React 错行

活动和已退休目标可能共享稳定业务 `target_key`。React 复用重复键后，筛选结果曾从每页 25 条错误显示为 33 条。现新增只用于渲染的 `row_key`，由业务键和目标 ID 组成；排除持久化仍使用原 `target_key`。桌面表格和移动卡片共用稳定行键，回归测试验证筛选后旧行消失且不产生重复键警告。

## 遗留风险

1. 固定渠道在首选目标因毛利不足被拒绝后，不会继续评估同渠道的下一条兼容目标。本轮必须临时调整目标优先级才能命中 Stable 933；应单独设计“同渠道候选继续回退”或“预计利润优先”的路由策略。
2. Paipu Stable 933 不支持 `execution_expires_after` 和 `return_last_frame`。Ark SDK 客户端若统一发送这些可选字段会被本地合同拦截，需要按目标能力省略，或为可安全忽略的字段定义统一兼容策略。
3. 动态档案继承 `default` 目录，因此上游配置重新导入后匹配数量会变化；上线维护应在批次激活前重新预览并运行 Canary。
4. 本轮只验收 `per_request` 真实成功路径。`per_duration`、`per_token`、真人能力 required/forbidden 的生产流量仍应按客户分组分别执行低成本 Canary。

# 渠道模型成本与利润模板转换器设计

## 1. 目标

建立一个可重复执行的转换器，把当前维护的 `sd收录.xlsx` 原始价格表转换为现有的“渠道模型成本与利润结构化模板”V1 Excel 文件，并输出可审计的校验报告。

转换器是生成模板的唯一入口。生成后的模板用于审核、利润测算和后续 new-api 配置导入，不作为下一次转换的输入源。

目标维护链路：

```text
sd收录.xlsx
        +
conversion-rules.json
        +
v1-base.xlsx
        |
        v
模板转换器
        |
        +--> 渠道模型成本与利润模板-v1.xlsx
        +--> 转换报告.json
        +--> 供现有 channel-config-converter 导入的 V1 模板
```

## 2. 已确认的输入和输出

### 2.1 原始表

当前原始文件包含以下权威输入表：

- `channel`：渠道编号、名称、价格页和 Base URL；当前 9 个渠道。
- `sd`：渠道级汇率、手续费、计费倍率、模型 ID、版本、计费模式、原币价格、素材限制、清晰度、视频能力、协议、状态和备注；当前约 115 条非空渠道模型记录。
- `sd官价`：官方模型、版本、清晰度、输入/输出视频价格、帧率、宽高和按秒预览价格。

`sd` 中的 `售价`、`利润` 和 `折扣*` 等派生或参考列不能被当作唯一事实源。转换器从原始价格、官方价格和规则文件重新计算模板中的派生字段。

### 2.2 规则文件

`conversion-rules.json` 保存原始表无法表达或不应依赖备注推断的业务规则：

- 模板版本和源工作表/表头签名；
- `渠道编号 -> 渠道代码` 和渠道类型映射；
- 模型 ID 的标准化、客户端模型、上游模型、版本和清晰度拆分规则；
- SKU 的宽、高、帧率、最短/最长时长及计量方法；
- `second`、`call`、`token` 到模板成本模式的映射；
- 汇率方向、默认费率、充值兑换比例、采购折扣和严格成本校验策略；
- 原表字段不足时的人工确认、排除或 `draft` 策略；
- 数据来源 ID、备注模板和状态映射；
- 初始模板参数，例如 `USD_CNY`、`TOKEN_DIVISOR` 和 `DEFAULT_GROUP_RATIO`。

规则文件必须是受版本控制的普通 JSON，金额、费率、倍率和汇率使用字符串 Decimal，不使用二进制浮点数。它不包含 API Key、Token 或其他渠道凭据。

### 2.3 模板基座

`v1-base.xlsx` 只保存现有模板的工作表、标题、说明、样式、表格、冻结窗格、公式模式和校验规则，不保存本次导入的渠道业务数据。它来源于当前修正版模板，后续样式调整只能在此基座中进行。

受管理的工作表为：`使用说明`、`参数`、`渠道`、`模型SKU`、`官方售价`、`渠道成本`、`模型映射`、`利润测算`、`来源`、`校验`。

### 2.4 输出

每次运行输出两个文件：

1. V1 Excel 模板，保留当前工作表顺序、列名、样式和公式，可直接人工审核；
2. JSON 转换报告，包含源文件 SHA-256、规则文件 SHA-256、转换器版本、生成时间、各实体数量、警告/错误、原始表名和行号、以及输出文件摘要。

输出 Excel 不回写原始文件，不保存凭据，不通过外部 URL 自动抓取价格。

## 3. 维护边界

日常价格或渠道变更时，维护人员更新 `sd收录.xlsx` 中的事实数据：渠道信息、渠道模型价格、官方价格、状态和原始备注。

只有在以下情况才修改 `conversion-rules.json`：

- 新增渠道编号或渠道类型；
- 原始表新增/改名列或工作表；
- 新模型的 ID 组合无法按现有规则拆分；
- 新计费模式、清晰度、视频能力或成本变体出现；
- 人工确认了此前的 `draft`、排除或冲突项；
- 汇率方向或默认业务假设发生变化。

模板基座只在版式、列结构或公式契约改变时维护。任何手工填写的业务规则都必须回写到规则文件，不能只写在一次生成的 Excel 中，否则下一次生成会丢失。

## 4. 实现边界

### 4.1 位置和命令

转换器放在 `web/scripts/channel-model-template/`，使用已有 Bun、TypeScript 和 `exceljs` 依赖；纯转换核心放在可被 Bun 测试和现有浏览器 converter 复用的模块中。

新增命令：

```text
bun --cwd web run channel-model-template:generate -- \
  --source "C:\\path\\sd收录.xlsx" \
  --rules "tools/channel-model-template/conversion-rules.json" \
  --base "tools/channel-model-template/v1-base.xlsx" \
  --output "outputs\\渠道模型成本与利润模板-v1.xlsx" \
  --report "outputs\\渠道模型成本与利润模板-v1.report.json"
```

命令默认严格模式：存在 `FAIL` 时不写入正式输出 Excel，只写报告和问题摘要。可以通过显式 `--allow-warnings` 允许 WARN 输出，但 WARN 对应行必须保持 `draft` 或不可激活状态。

### 4.2 处理阶段

1. 校验文件扩展名、大小、工作表数量和表头签名；
2. 读取 `channel`、`sd`、`sd官价` 的值和原始行号，不执行或信任 Excel 外部链接；
3. 对文本、枚举、日期、整数和 Decimal 做规范化；
4. 按规则文件生成渠道、SKU、官方售价、渠道成本、模型映射、利润场景和来源实体；
5. 重新计算标准 USD 成本、官方 USD 售价、Token 估算、渠道成本、用户收入、毛利润和毛利率；
6. 运行结构、引用、重复、范围、公式和业务策略校验；
7. 在基座中清空受管理数据区，写入规范化输入并填充模板公式；
8. 更新 `参数`、`使用说明` 的导入摘要和 `校验` 工作表；
9. 写入输出 Excel 和转换报告。

### 4.3 复用现有 converter

现有 `web/src/channel-config-converter` 已能识别 V1/V2 模板并生成安全的 new-api 配置导入 JSON。新转换器生成的 V1 Excel 必须通过现有 V1 adapter 的识别和转换测试。

两条链路保持职责分离：

- 模板转换器：`sd收录.xlsx -> V1 Excel`，服务于维护、审核和利润测算；
- 现有配置转换器：`V1/V2 Excel -> new-api JSON`，服务于配置导入。

不得把模板生成逻辑复制到浏览器页面，也不得让浏览器 converter 依赖本地路径或后端网络。

## 5. 字段映射和实体规则

### 5.1 渠道

从 `channel` 生成渠道主数据：

- 渠道编号通过规则文件转换为 `CH-*` 渠道代码；
- 名称、价格页和默认币种写入 `渠道`；
- `充值兑换比例`、`手续费率`、`计费倍率`、严格校验和状态使用规则文件与 `sd` 的渠道级字段合并；
- 每个渠道必须有唯一代码和来源 ID。

### 5.2 模型 SKU

从 `sd官价` 生成官方 SKU；从 `sd` 中出现但官方矩阵缺失的清晰度生成 `draft` SKU。SKU 的业务 ID 由标准化模型、版本和清晰度组成，不能使用可变的原始行号作为主键。

SKU 必须拥有正的宽、高、帧率、最小时长和最大时长，且最大时长不小于最小时长。宽高、帧率和时长来源必须能追溯到 `sd官价`、`sd` 或规则文件。

### 5.3 官方售价

按 `客户端模型 + SKU + 定价场景` 生成售价行。无视频和含视频场景使用 `sd官价` 的对应价格；USD 字段由规则中的汇率计算，不能直接读取 `sd` 的参考折扣列。

### 5.4 渠道成本

按 `渠道 + 上游模型 + SKU + 定价场景` 生成成本规则。`sd` 的计费列映射为：

- `second` -> `per_duration`，使用原币/秒；
- `call` -> `per_request`，使用原币/次；
- `token` -> `per_token`，使用原币/1M。

标准 USD 单价使用统一公式：

```text
原币价格 × 计费倍率 × 采购折扣
÷ 充值兑换比例 × (1 + 手续费率)
× 原币兑 USD 汇率
```

采购折扣是否参与成本计算由规则文件明确。当前修正版模板的初始策略为原表折扣仅作为参考，`采购折扣=1`，并在备注保留原始折扣，避免重复乘入成本。

### 5.5 模型映射和利润测算

每条可解析成本规则生成一个客户端模型到渠道上游模型的映射；无法确认清晰度、上游模型或成本变体的行进入 `draft`/待确认，不静默猜测。

利润测算仅对同时存在官方售价和渠道成本的组合生成。输出收入、成本、毛利润和毛利率必须由模板公式驱动；转换器只写入经过规范化的事实输入和场景参数。

## 6. 校验和失败策略

至少执行以下校验：

- 文件、工作表和表头签名；
- 渠道、SKU、售价、成本和映射的重复业务 ID；
- 跨表引用存在性；
- 价格、汇率、费率、倍率和时长的数值范围；
- 清晰度、版本、计费模式和定价场景可识别；
- 成本模式与实际价格列一致；
- 官方售价和渠道成本组合是否完整；
- 公式写入后关键区域没有 `#REF!`、`#VALUE!`、`#DIV/0!`、`#N/A`；
- 转换结果是否通过现有 V1 converter 的模板识别。

错误分为：

- `FAIL`：阻止正式 Excel 输出，必须修复源表或规则文件；
- `WARN`：允许生成但受影响实体保持 `draft`/不可激活，并写入报告；
- `INFO`：记录正常的拆分、默认值或来源信息。

每个问题必须包含稳定代码、严重级别、工作表、行号、字段、业务 ID、消息和修复建议。

## 7. 确定性、版本和审计

转换器版本写入报告和 `参数!B10`。同一源文件、规则文件和基座版本必须产生相同的业务 ID、行排序、实体计数和规范化数值；`generated_at` 只用于审计显示，不参与业务 ID。

报告保存：

- 源文件名和 SHA-256；
- 规则文件和基座版本/哈希；
- 转换器版本；
- 各工作表和实体数量；
- 每个实体的原始工作表与行号；
- 所有 FAIL/WARN/INFO；
- 输出文件路径和摘要哈希。

历史生成文件不被覆盖。命令应在输出路径已存在时拒绝覆盖，除非显式提供 `--force`。

## 8. 测试策略

先为纯转换核心编写失败测试，再实现转换器：

1. 当前 `sd收录.xlsx` 的 9 个渠道、115 条原始记录、官方价格矩阵和关键成本模式能够生成预期实体计数；
2. `second`、`call`、`token` 的成本模式和标准 USD 单价符合公式；
3. 缺少官价、清晰度或上游模型时产生稳定 WARN/FAIL，不生成可激活规则；
4. 重复渠道/重复 SKU/断开引用被拒绝；
5. 相同输入生成相同业务 ID、排序和报告摘要；
6. 生成的 V1 模板能被现有 `channel-config-converter` 识别；
7. 模板关键公式区域不包含明显错误；
8. 输出路径存在时默认不覆盖，`--force` 才允许替换；
9. 源文件包含宏、外部链接、超大表或未知表头时阻止生成；
10. 规则文件不含凭据、非有限数值或负价格。

使用 Bun 测试和最小的固定 fixture；不使用随机、sleep、性能或仅证明代码运行的测试。

## 9. 非目标

- 不自动访问渠道价格页；
- 不修改 `sd收录.xlsx`；
- 不将人工维护的输出 Excel 反向合并回源表；
- 不在本阶段替换 new-api 的配置导入后端；
- 不把利润预览当作真实结算账本；
- 不制作依赖 AI 判断的不可重复 agent 流程。

## 10. 验收标准

使用现有 `sd收录.xlsx` 和修正版模板作为固定回归样本，转换器能够：

1. 在本地无网络环境运行；
2. 生成与当前 V1 模板相同的工作表和列结构；
3. 保留 9 个渠道、官方价格、渠道成本、模型映射、利润测算和来源追溯；
4. 对无法自动确认的项目显示明确 WARN/FAIL，而不是静默填充；
5. 生成的 V1 Excel 可被现有配置转换器继续转换为 new-api JSON；
6. 日常只更新原始事实表，规则变化才更新规则文件，模板样式变化才更新基座；
7. 任何一次生成都能通过报告追溯到源文件、规则版本、转换器版本和原始行号。

# 利润报表可编辑下拉筛选设计

## 目标

将成本核算“利润报表”中的渠道 ID、计费上游模型、原始模型、用户分组和使用分组从纯文本输入框改为可搜索、可清除、允许自由输入的下拉选择框。交互与使用日志页面保持一致，同时候选值必须来自成本核算账本的实际历史记录。

## 范围

本次只调整利润报表筛选区及其候选数据接口。日期、计费来源、利润状态、报表聚合和 URL 参数语义保持不变。

## 交互设计

- 五个字段均使用项目现有 `Combobox`，聚焦后展示候选，输入时本地过滤，候选项可点击或通过键盘选择。
- 每个字段允许自由输入，以便筛选历史值、已删除渠道关联的值或暂未出现在候选中的值。
- 渠道候选标签为 `ID - 渠道名`，提交值仅为正整数 ID；其余字段标签和提交值均为原始字符串。
- 清除控件只清除当前草稿字段；点击“应用筛选”前不改变 URL、不重新请求利润汇总或列表。
- 候选接口基于已应用的 URL 筛选范围，而不是未提交草稿。这样候选列表与当前报表一致，并避免输入过程频繁请求。

## 候选数据与接口

新增只读接口 `GET /api/cost-accounting/reports/filter-options`，接受与利润报表相同的查询参数和时间口径，返回：

```json
{
  "channels": [{ "id": 12, "name": "供应商 A" }],
  "billable_upstream_models": ["vendor-model"],
  "origin_models": ["client-model"],
  "user_groups": ["default"],
  "using_groups": ["premium"]
}
```

候选统一从 `cost_accounting_requests` 与 `cost_accounting_attempts` 中读取，而不从当前渠道配置、模型配置或用户分组配置读取。因此历史账本、已停用渠道和已删除配置仍可被准确筛选。

每个候选集合应用其余已提交筛选，但移除自身对应筛选，避免自我限制：例如获取原始模型候选时保留渠道、上游模型和分组条件，但忽略 `origin_model`。时间范围与利润报表使用相同的 `time_basis` 条件。

渠道与计费上游模型通过尝试账本查询取得；原始模型、用户分组、使用分组通过请求账本查询取得。数据库读取使用 GORM 的可移植查询，结果在服务层去空、去重并稳定排序，避免依赖某个数据库方言的字符串聚合函数。

## 前端结构

- 增加成本核算筛选候选的 TypeScript 类型、API 方法及 React Query 键。
- 新增一个专用 hook，负责用当前已提交的利润筛选加载候选，并将渠道数据转换为 `Combobox` 选项。
- `ProfitFilters` 接收候选选项或调用该 hook，五个字段替换为统一的可编辑下拉字段；日期字段仍使用 `Input`。
- 组合框沿用使用日志的 `allowCustomValue`、`openOnFocus` 以及 IME composition 处理，避免中文输入过程中提前更新草稿。

## 错误处理与兼容性

- 候选加载失败不得阻塞利润报表，也不得清除用户当前草稿；组合框仍可自由输入。
- 现有 URL 参数继续生效；候选列表中缺失当前 URL 值时，输入框仍显示且可应用。
- 渠道 ID 继续只接受正整数；无效输入在应用时按当前行为清空该筛选，不发送非法参数。

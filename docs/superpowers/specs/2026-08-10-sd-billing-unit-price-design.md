# sd 收录表最新版结构与完整刷新设计

## 背景

最新版 `sd收录` Google 表格同时调整了模型、计费和素材能力字段：

- `sd` 工作表在 `模型ID` 后新增 `系列`，用于区分 Seedance 2.0、2.5 等系列；
- 删除 `元/秒`、`元/次`、`元/1M`，改为 `计费方式 + 单价 元`；
- 删除 `视频输入`，是否支持视频输入改由 `参考视频数` 判定；
- `sd官价` 工作表也新增 `系列`，并已包含 Seedance 2.5 官方价格行。

2026-08-10 下载的权威源表中，`sd` 实际范围为 `A1:AM1058`，表头不再包含 `视频输入`；有效模型行的 `参考视频数` 当前为 `0` 或 `3`。`sd官价` 实际范围为 `A1:L16`，其中已有 `系列=2.5`、`模型=seedance-2.5` 的 480p 和 720p 价格。

## 目标与边界

- 生成器只接受最新版 `sd` 和 `sd官价` 表头契约，不兼容旧价格列或旧 `视频输入` 列。
- `second`、`call`、`token` 分别规范化为内部 `per_duration`、`per_request`、`per_token`，统一从 `单价 元` 读取人民币原始单价。
- `参考视频数 > 0` 表示支持视频输入，`参考视频数 = 0` 表示不支持；空值、负数、非整数和其他非法值继续作为素材合同问题处理，不能被静默判定为支持。
- `系列` 进入源表解析和官方价格匹配键，防止未来 Seedance 2.0 与 2.5 发生交叉匹配。
- 本次不修改 V1 模板列结构、配置导入 JSON schema、利润公式或运行时 Seedance 2.5 协议能力。2.5 在尚无渠道模型行时只作为可解析的官方价格事实保留。
- 完整刷新默认使用 Mock 上游 Ark SDK E2E，不访问真实收费上游。

## 方案选择

采用“严格源表边界规范化 + 系列感知匹配”方案。

`source.ts` 负责严格识别最新版表头，并把源表字段规范化为构建层需要的稳定字段；`build.ts` 只消费统一单价、系列和结构化素材合同。官方价格索引使用“系列 + 模型 + 分辨率”，SKU 的视频输入能力由同一份结构化素材合同推导。

不保留新旧表头兼容分支，避免过期工作簿被误发布；不只做表头放行而忽略 `系列`，避免后续 2.5 数据接入时再次修改匹配边界。

## 设计

### 源表读取

`source.ts` 只保留一个最新版 `SD_HEADERS`：核心顺序为 `渠道`、`充值汇率`、`手续费`、`计费倍率`、`付费模式`、`模型ID`、`系列`、`版本`、`清晰度`、`计费方式`、`单价 元`，后续为结构化素材合同、能力、状态、折扣和备注字段，不再包含 `视频输入`。

读取后将 `计费方式` 规范化为内部 `计费`，保留 `单价 元` 和 `系列`。检测到旧价格列、旧 `视频输入`、缺失新字段、重复表头或新旧混用时，抛出可定位的 `sd header mismatch`，不得回退旧结构。

`OFFICIAL_PRICE_HEADERS` 增加 `系列`。`系列` 接受有限正数或可无损规范化的数字文本，不使用固定系列白名单；空值或非法数值生成阻断问题，不自动猜测系列。

`sd` 中存在只填写 `系列` 的分组行。读取模型记录时只用 `渠道` 和 `模型ID` 等模型身份字段判定有效行，不能因为分组行填写了 `系列` 就把它当作渠道模型；对应测试固定这一过滤契约。

### 视频输入能力

结构化素材合同继续统一校验 `参考图数`、`参考视频数`、`参考音频数`、总素材数和视频时长等约束。删除原有“`视频输入=否` 但参考视频数大于 0”的交叉校验。

生成 SKU 时复用已校验素材合同：

- `videos > 0`：`supportsVideoInput = 是`；
- `videos = 0`：`supportsVideoInput = 否`；
- 素材合同非法：对应映射和成本保持 `draft`，并记录问题，不把非法值当作支持能力。

模型映射备注仍保留 `参考视频数`，使转换后的能力合同可以审计到源表数值。

### 系列与官方价格匹配

官方价格索引键改为 `系列 + 模型 + 分辨率`。从渠道模型生成 SKU、售价和成本映射时使用渠道行的 `系列`；只有系列、标准模型名和分辨率同时一致时才匹配官方价格。

V1 模板暂不新增独立“系列”列。模型名继续承担对外身份，例如 `seedance-2.0`、`seedance-2.5`；系列只在源表边界和构建期匹配中使用。这样不会改变现有导入 schema，同时为未来新增 2.5 渠道模型行建立明确匹配规则。

### 成本构建

`build.ts` 保留 `COST_MODES` 映射，统一解析 `单价 元`。计费模式只影响 `CostRow.mode`、单位、计费事件字段和利润公式。单价必须是有限且大于零的数值；空值、零值、负值和非数值产生 `COST_PRICE_INVALID` 警告并将成本和映射置为 `draft`。未知计费方式继续产生 `COST_MODE_UNKNOWN` 失败。

### 完整刷新流程

代码和 focused tests 通过后，使用已登录 Chrome 重新下载权威源表到唯一输出目录，完成：

1. 源表结构、公式和值校验，并渲染全部工作表；
2. 生成模板和 JSON 报告，要求 `FAIL=0`，逐项解释 `WARN` 和 `draft`；
3. 校验模板全部受管理工作表、公式和按次/按秒/Token 利润样本；
4. 通过本地 `/config-import` 导出选中配置 JSON，按状态机完成绑定、审阅、发布和激活；
5. 运行 `TestSeedanceImportedMaterialMatrixFullFlowE2E` 及 focused 回归；
6. 生成简体中文验收报告，记录哈希、计数、批次、激活、E2E 和设置恢复结果。

任一阶段出现生成 `FAIL`、无法解释的价格单位、导入 error、绑定歧义、激活 blocker 或缓存状态不确定时，停止后续流程并保留证据。

## 测试策略

按 TDD 执行：

1. 先更新测试 fixture，使其包含 `系列`、`计费方式`、`单价 元`，删除旧价格列和 `视频输入`；新增读取测试并确认旧实现失败。
2. 增加旧表头拒绝、新旧混用拒绝、缺失 `系列`/`单价 元`、非法系列、仅含系列的分组行过滤、三种计费模式和非法单价测试。
3. 增加 `参考视频数=0` 与大于 0 的 SKU 能力测试，并保留非法素材合同门禁测试。
4. 增加 2.0/2.5 同分辨率价格隔离测试，证明官方价格不会跨系列匹配。
5. 实现最小解析和构建改动，运行 `channel-model-template`、`channel-config-converter`、类型检查和涉及文件 lint。
6. 用真实下载源表生成模板，执行结构、公式、视觉、转换和 Mock Ark SDK E2E 验证。

测试只保护源表契约、能力推导、系列隔离、成本模式和发布门禁，不锁定无关内部实现。

## 验收与回滚

只有在源表无公式错误、生成报告 `FAIL=0`、所有 `WARN/draft` 可解释、模板转换无 error、导入审阅及激活预检通过后，才更新仓库源表并激活新批次。

本轮所有下载物、模板、报告、选中配置 JSON、导入问题和 E2E 日志写入唯一 `outputs/YYYY-MM-DD-<run-name>` 目录。任何失败都保留旧仓库源表和已激活批次，不运行真实供应商 Canary。

# 供应商成本目录设计

## 1. 背景

成本核算已经维护版本化的渠道模型成本规则，并能在请求详情、异常队列和利润报表中展示实际结算结果。但是管理员目前缺少一个全局只读目录，无法一次查看、筛选和导出全部供应商合同成本。

现有 `GET /api/cost-accounting/rules` 面向规则维护流程，只支持 `channel_id`、`billable_upstream_model` 和 `cost_variant_key` 三个精确筛选条件，返回未分页的原始规则数组，也不包含渠道名称和类型。前端如果再分别读取渠道并自行关联，会产生权限边界分散、筛选口径不一致、数据量不可控和导出结果难以复现等问题。

本设计在现有成本核算页面增加“供应商成本目录”，为具备成本核算读取权限的管理员提供统一、可审计的合同成本查询入口。

## 2. 目标

首版实现以下能力：

1. 在 `/cost-accounting` 内查看全部渠道模型成本规则；
2. 按渠道、计费上游模型、成本模式、规则状态、币种和来源筛选；
3. 查看原币合同价格、标准化 USD 价格、计费单位和换算参数；
4. 查看规则版本、有效期、备注和同一业务键的历史；
5. 导出当前筛选结果或全部供应商成本；
6. 在桌面端和移动端保持可读、可操作和可访问；
7. 保持供应商成本、严格模式和利润路由的既有结算语义不变。

## 3. 范围

### 3.1 首版范围

首版严格只读，仅包含查看、筛选、排序、分页、刷新、详情和导出。目录读取现有 `channel_model_cost_rules` 与渠道身份，不新增成本规则、渠道或历史数据来源。

### 3.2 不在首版范围

- 不在目录内创建、编辑、激活或退休成本规则；
- 不修改现有配置导入、批次发布和批次激活流程；
- 不改变供应商成本结算、严格模式预检或利润路由算法；
- 不自动同步供应商价格或汇率；
- 不新增侧边栏入口；
- 不把目录放入渠道管理页面；
- 不导出 API Key、Base URL、请求头、代理、渠道扩展配置或其他凭据；
- 不从历史请求实际成本反推合同单价。

后续可以在渠道页面增加携带 `channelId` 的“查看成本”深链，但不属于首版交付。

## 4. 信息架构决策

### 4.1 采用方案：成本核算页第三个 Tab

页面保持现有一级入口 `/cost-accounting`，增加 URL 驱动的第三个 Tab：

1. `利润报表`：`tab=profit`；
2. `供应商成本目录`：`tab=catalog`；
3. `异常`：`tab=anomalies`。

目录标准地址为：

```text
/cost-accounting?tab=catalog
```

采用该方案的原因：

- 供应商合同成本、请求实际成本和利润报表属于同一成本核算域；
- 复用现有 `cost_accounting.read` 页面权限和管理员认知路径；
- 避免为首版只读视图增加新的侧边栏层级；
- 后续从利润报表、异常记录或渠道页跳转时仍有稳定 URL。

### 4.2 未采用方案

独立侧边栏页面未采用，因为首版功能集中且与成本核算高度关联，会增加导航和权限维护成本。

渠道页面内的 Tab 未采用，因为成本规则可以包含历史版本、多个成本变体和跨渠道筛选，职责不等同于单个渠道配置。

弹窗或抽屉作为唯一入口未采用，因为全量筛选、分页和导出需要稳定页面状态和可分享 URL。

## 5. 页面结构

### 5.1 桌面端布局

目录 Tab 使用紧凑、工作台式布局：

```text
成本核算标题、模式与全局毛利率设置
利润报表 | 供应商成本目录 | 异常

渠道数 | 活动规则 | 草稿规则 | 已退休规则        刷新 | 导出当前结果 | 导出全部

渠道 | 计费上游模型 | 成本模式 | 状态 | 币种 | 来源

渠道          计费上游模型      成本变体   状态/版本   成本模式
原币价格      标准化 USD 价格   计费语义   来源        有效期
```

摘要区不使用独立嵌套卡片，采用同一内容区内的紧凑统计带。渠道和模型列固定在表格左侧，其余列横向滚动。表格行高和操作区尺寸保持稳定，加载或展开详情不能导致表头和工具栏跳动。

摘要统计遵循以下口径：

- 渠道数按规则关联后的不同 `channel_id` 计数；
- 活动、草稿和已退休规则按规则版本行计数；
- 摘要应用渠道、模型、成本模式、币种和来源筛选，但忽略状态筛选；
- 因此切换状态时仍可看到当前业务范围内各状态的完整分布。

### 5.2 移动端布局

移动端不强行压缩桌面宽表。每条规则渲染为紧凑可展开项，默认显示：

- 渠道名称和 ID；
- 计费上游模型；
- 成本模式与规则状态；
- 主要标准化 USD 单价。

展开后显示成本变体、原币价格、计费语义、来源、版本和有效期。点击整行仍打开完整详情抽屉；展开控件和详情操作必须是两个可区分的键盘焦点。

### 5.3 筛选器

首版支持：

| 筛选项 | 交互 | 语义 |
| --- | --- | --- |
| 渠道 | 可搜索选择器 | 精确匹配 `channel_id` |
| 计费上游模型 | 文本搜索 | 服务端包含匹配，去除首尾空格 |
| 成本模式 | 单选菜单 | `free`、`per_request`、`per_duration`、`per_token` |
| 状态 | 单选菜单 | 默认 `active`，可选 `draft`、`retired`、全部 |
| 币种 | 单选菜单 | 规范币种代码精确匹配 |
| 来源 | 单选菜单 | 规则 `source` 精确匹配 |

筛选器提供统一“清除筛选”操作。清除后恢复 `status=active`、第一页和默认排序，不清除当前 `tab=catalog`。

### 5.4 命令

- 刷新：保留筛选、排序、分页和当前旧数据，后台重新请求；
- 导出当前结果：导出全部符合当前筛选的规则，不受当前页限制；
- 导出全部：忽略目录筛选，导出所有状态和全部渠道的成本规则。

导出期间仅禁用被触发的导出按钮。按钮使用下载或刷新图标并提供可访问名称；不熟悉的图标同时提供 Tooltip。

## 6. URL 状态

目录筛选、排序和分页保留在 TanStack Router 的查询参数中。由于利润报表已经使用 `channelId`、`billableModel` 和 `status`，目录使用 `catalog` 前缀隔离状态，避免切换 Tab 时把利润状态误解释为规则状态。

| 页面参数 | API 参数 | 默认值 |
| --- | --- | --- |
| `catalogChannelId` | `channel_id` | 空 |
| `catalogModel` | `billable_upstream_model` | 空 |
| `catalogCostMode` | `cost_mode` | 空 |
| `catalogStatus` | `status` | `active` |
| `catalogCurrency` | `currency` | 空 |
| `catalogSource` | `source` | 空 |
| `catalogPage` | `page` | `1` |
| `catalogPageSize` | `page_size` | `50` |
| `catalogSort` | `sort_by` | `channel_name` |
| `catalogOrder` | `sort_order` | `asc` |

`catalogStatus=all` 映射为 API 的 `status=all`，表示不添加规则状态条件；空值和缺省值都按 `active` 处理。`page_size` 只接受 `25`、`50` 或 `100`。无效枚举由前端路由 schema 回退到默认值，后端仍独立校验所有查询参数。

模型搜索按字面量执行不区分大小写的包含匹配；用户输入中的 `%` 和 `_` 不能被解释为 SQL 通配符。切换任何筛选或排序后回到第一页。

示例：

```text
/cost-accounting?tab=catalog&catalogStatus=active&catalogChannelId=23&catalogCostMode=per_request&catalogPage=1
```

## 7. 后端 API

### 7.1 目录列表

新增：

```http
GET /api/cost-accounting/catalog
```

接口由服务端完成渠道关联、过滤、排序、分页、价格投影和摘要统计。响应结构为：

| 字段 | 含义 |
| --- | --- |
| `items` | 当前页目录行 |
| `total` | 符合全部筛选条件的规则数 |
| `page` | 当前页 |
| `page_size` | 每页数量 |
| `summary.channel_count` | 忽略状态筛选后的渠道数 |
| `summary.active_rule_count` | 忽略状态筛选后的活动规则数 |
| `summary.draft_rule_count` | 忽略状态筛选后的草稿规则数 |
| `summary.retired_rule_count` | 忽略状态筛选后的已退休规则数 |
| `facets.channels` | 目录中出现的渠道 ID、名称和类型 |
| `facets.currencies` | 可用的规范币种代码 |
| `facets.sources` | 可用的规则来源 |

`facets` 基于管理员有权读取的完整成本目录生成，不随当前筛选缩减，避免选中筛选后其他选项消失。成本模式和规则状态是固定枚举，不由接口重复返回。前端不得依赖渠道管理接口填充目录筛选器，因此仅具备 `cost_accounting.read` 的管理员也能完整使用目录。

允许的排序字段采用后端白名单：`channel_name`、`channel_id`、`billable_upstream_model`、`cost_variant_key`、`status`、`version`、`cost_mode`、`source` 和 `effective_from`。默认按渠道名称、渠道 ID、计费上游模型、成本变体、版本倒序形成稳定顺序；所有排序最后追加规则 ID，避免翻页重复或遗漏。

### 7.2 目录详情

新增：

```http
GET /api/cost-accounting/catalog/:rule_id
```

详情返回：

- 当前选中规则的完整目录投影；
- 完整规范成本配置；
- 换算参数与标准化 USD 价格；
- `note`、创建人、激活人和时间字段；
- 同一 `channel_id + billable_upstream_model + cost_variant_key` 的版本历史。

实现复用现有规则读取和 `CostRuleHistory` 业务语义。现有 `GET /api/cost-accounting/rules/:id/history` 保持不变，避免破坏已有调用方。

### 7.3 CSV 导出

新增：

```http
GET /api/cost-accounting/catalog/export
```

导出接口复用列表的筛选和排序合同，并增加：

| 参数 | 含义 |
| --- | --- |
| `scope=filtered` | 应用当前目录筛选，忽略分页 |
| `scope=all` | 忽略目录筛选，导出所有状态和全部渠道 |

`scope` 为必填参数，后端只接受上述两个值，不能以缺省值推断全量导出。首版导出上限为 100,000 行；导出前先计数，超过上限时在发送文件头前返回 `413` 和明确错误，不生成静默截断文件。

CSV 使用 UTF-8 BOM 和 `text/csv; charset=utf-8`，通过 `Content-Disposition` 提供包含范围和时间的文件名，例如：

```text
供应商成本目录-全部-20260809-153000.csv
```

`Content-Disposition` 同时提供 ASCII 回退文件名和 RFC 5987 `filename*` 中文文件名；`X-Exported-Row-Count` 返回实际导出行数，供前端成功提示使用。

CSV 每列使用标准库 CSV 编码器处理逗号、引号和换行。可能由渠道名称、模型、成本变体、来源或备注等外部文本进入的单元格，在去除用于判定的前导空白后如以 `=`、`+`、`-` 或 `@` 开头，必须加单引号前缀，防止 Excel 公式注入。

CSV 不包含渠道密钥、Base URL、请求头、代理、渠道 `Other`、`Setting`、`ParamOverride`、`HeaderOverride`、管理员账号详情或原始未验证 JSON。

CSV 使用固定结构化列，不导出 `config_json` 原文。列顺序为：

1. 渠道名称、渠道 ID、渠道类型；
2. 规则 ID、计费上游模型、成本变体、规则状态、版本、Schema 版本；
3. 成本模式、币种；
4. 每次原币单价、每秒原币单价、每 1M 总 Token 原币单价、每 1M Completion Token 原币单价、每 1M 输入 Token 原币单价、每 1M 输出 Token 原币单价；
5. 与上一项逐一对应的标准化 USD 单价；
6. 15 秒等效 USD/秒（仅比较）；
7. 计费倍率、采购折扣率、充值换算率、费率、兑 USD 汇率；
8. 收费事件、计量来源、Token 子模式、免费原因；
9. 来源、备注、生效时间、失效时间、创建时间、更新时间；
10. 价格状态和问题代码列表。

不适用于当前成本模式的价格列留空。配置缺失或无效时相关价格列留空，并通过不可用原因说明，不能填 `0`。

## 8. 目录投影

### 8.1 公共规则与渠道身份

每行包含以下明确白名单字段：

- 规则：`rule_id`、`version`、`status`、`schema_version`、`cost_mode`、`source`、`note`；
- 业务键：`channel_id`、`billable_upstream_model`、`cost_variant_key`；
- 渠道：`channel_name`、`channel_type`；
- 计费语义：`charge_event`、`meter_source`、`token_mode`；
- 时间：`effective_from`、`effective_to`、`created_at`、`updated_at`；
- 价格：模式相关价格项、币种、标准化 USD 价格和只读比较值；
- `price_status`：`available` 或 `unavailable`，明确价格是否可展示；
- `issues`：问题代码数组，可同时包含 `channel_missing`、`invalid_config` 或 `missing_normalized_price` 等原因。

渠道已删除或无法关联时，规则仍保留在结果中，`channel_name` 显示“未知渠道”，并在 `issues` 中返回 `channel_missing`。渠道缺失本身不把有效价格改成不可用；不能因为渠道关联失败而丢失历史成本规则。

### 8.2 价格项

API 返回结构化十进制字符串和语义标识，不返回已经本地化的展示文本。前端负责币种符号、单位文案和数字格式。

| 成本模式 | 价格项 | 原币字段 | 标准化 USD 字段 | 单位 |
| --- | --- | --- | --- | --- |
| `free` | 无价格项 | 无 | 无 | 免费原因 |
| `per_request` | 每次单价 | `unit_price` | `normalized_usd_prices.unit_price` | 每次 |
| `per_duration` | 每秒单价 | `price_per_second` | `normalized_usd_prices.price_per_second` | 每秒 |
| `per_token/total_tokens` | 总 Token 单价 | `total_per_million` | 同名标准化字段 | 每 1M Token |
| `per_token/completion_tokens` | 输出 Token 单价 | `completion_per_million` | 同名标准化字段 | 每 1M 输出 Token |
| `per_token/input_output` | 输入、输出两个价格项 | `input_per_million`、`output_per_million` | 对应标准化字段 | 每 1M Token |

原币价格表示供应商合同配置中的模式价格；标准化 USD 价格表示现有规则激活时已经校验并保存的 `normalized_usd_prices`。目录不得使用运行时汇率重新计算历史规则，也不得从请求实际成本反推单价。

### 8.3 换算参数

详情抽屉展示现有规范配置中的：

- `currency`；
- `billing_multiplier`；
- `purchase_discount_ratio`；
- `recharge_exchange_ratio`；
- `fee_rate`；
- `currency_to_usd_rate`。

列表只展示原币和标准化 USD 结果，避免在宽表中堆叠所有中间参数。缺少字段不自动显示为 `0` 或 `1`；前端根据成本规则规范区分“未使用”和“不可用”。

### 8.4 按次规则的 15 秒等效价格

`per_request` 规则额外提供：

```text
comparison_15s_equivalent_usd_per_second =
    normalized_usd_prices.unit_price / 15
```

该字段的名称和 UI 标签固定包含“15 秒等效”和“仅比较”。它只用于把按次报价与按秒官方报价放在同一尺度下人工比较。

以下边界属于强制合同：

- 供应商实际成本仍是完整按次成本；
- 4 秒、10 秒或其他时长的请求不能按该等效秒价折算成本；
- 严格模式、利润预检、模型路由和结算不得读取该字段；
- 比较值不写回 `channel_model_cost_rules`，不进入成本尝试快照；
- 导出列名必须包含“仅比较”，不得命名为“实际每秒成本”。

计算使用项目既有高精度 Decimal 能力，返回规范十进制字符串。原始 USD 单价缺失、无效或为负时不生成比较值，并返回对应不可用原因。

## 9. 数据访问与分层

实现遵循 `Router -> Controller -> Service -> Model`：

- Router 注册三个只读 GET 路由并应用 `CostAccountingRead`；
- Controller 解析并校验查询参数，输出目录 DTO 或 CSV；
- Service 负责目录投影、配置解析、比较值、摘要和导出语义；
- Model 使用 GORM 执行渠道左连接、普通列筛选、计数、稳定排序，并在不按币种筛选时完成数据库分页。

目录不能在前端分别请求全部规则与渠道后进行内存关联。列表和导出必须调用同一筛选构造逻辑，防止页面与 CSV 口径漂移。

数据库查询要求：

- 兼容 SQLite、MySQL 5.7.8+ 和 PostgreSQL 9.6+；
- 使用 GORM 表达式和参数绑定，不依赖数据库 JSON 运算符；
- 对渠道使用左连接，保留孤立历史规则；
- 对币种筛选所需的 `config_json` 不使用方言相关 JSON 查询。

由于币种当前存储在规范 JSON 文本中，首版采用跨数据库兼容的条件分支：未指定币种时由数据库直接计数和分页；指定币种时先用普通列缩小候选集，再由 Service 分批读取并解析规范配置，完成币种过滤、总数和当前页截取。facets 的币种集合也通过仅选择规则 ID 与 `config_json` 的分批查询生成。不能为方便查询临时加入方言专属 JSON 运算符或字符串匹配 JSON。

所有 JSON 解析和生成使用 `common` JSON 包装函数。

## 10. 权限与保密边界

三个新接口统一使用：

```text
AdminAuth + cost_accounting.read
```

首版不新增权限资源，也不要求 `cost_accounting.write`。目录接口只接受 GET，不提供任何修改规则的操作。

返回 DTO 采用编译期白名单，不直接序列化 `Channel` 数据库模型或任意 `map`。该目录属于管理员供应商敏感信息，与《供应商敏感信息日志边界设计》保持一致：普通用户 API、普通使用日志和普通任务日志不得引用、转发或深链到目录数据。

接口错误不得包含原始 `config_json`、渠道密钥、Base URL 或未脱敏数据库错误。服务端日志可以记录规则 ID、渠道 ID 和错误类别，但不能记录凭据。

## 11. 加载、空状态与错误处理

### 11.1 列表

- 首次加载显示固定行高的表格骨架；
- 刷新保留旧数据并显示轻量加载状态；
- 系统没有任何规则时显示“暂无供应商成本规则”；
- 有规则但筛选无结果时显示“没有符合条件的规则”和“清除筛选”；
- 查询失败时在表格区域显示安全错误摘要和“重试”；
- 列表失败不清空筛选条件。

### 11.2 数据不可用

无效 JSON、缺少模式字段、缺少标准化 USD 价格或无法关联渠道时，单行返回明确的投影状态和原因。页面显示“未知”或“不可用”，不能显示为 `$0`，也不能让单条坏数据导致整个目录失败。

### 11.3 详情抽屉

点击一行打开只读详情抽屉。抽屉独立加载，失败时只影响抽屉并提供重试。关闭抽屉后焦点返回原行；切换到另一行时取消或忽略旧请求结果，避免显示错位详情。

### 11.4 导出

- 成功后显示文件名和导出行数；
- 失败时显示安全错误原因并允许重试；
- 权限失效时遵循全局鉴权处理；
- 超过资源限制时明确提示缩小筛选范围；
- 不生成无说明的空文件或静默截断文件。

## 12. 国际化与可访问性

所有新增前端文案使用 `useTranslation()`，以英文源字符串为键，并同步 `en`、`zh`、`zh-TW`、`fr`、`ru`、`ja`、`vi` 全部语言文件。

可访问性要求：

- 三个 Tab 使用现有 Tabs 组件语义并支持键盘切换；
- 筛选控件具有可见标签或等价可访问名称；
- 表头排序状态通过 `aria-sort` 暴露；
- 状态同时使用文本，不只依赖颜色；
- 图标按钮具有 `aria-label`，不熟悉的图标提供 Tooltip；
- 抽屉打开后焦点进入标题或首个可操作元素，关闭后返回触发行；
- 移动端展开按钮具有 `aria-expanded` 与目标关联；
- 加载和导出结果使用非阻塞状态通知，不反复打断屏幕阅读器。

## 13. 性能与一致性

- 列表默认每页 50 条，只允许 25、50、100；
- 查询不得逐行读取渠道，禁止 N+1；
- 目录列表与 CSV 共用筛选、排序、投影和不可用原因实现；
- 摘要统计和列表使用同一筛选快照，不能出现列表已刷新但摘要仍是旧条件的状态；
- React Query 缓存键包含全部目录参数；
- 只有 `tab=catalog` 时才请求目录数据；
- 抽屉历史在打开时按需加载；
- 导出按服务端资源上限保护内存和执行时间。

首版不新增数据库表。若实施性能测试证明现有索引不足，只允许增加兼容三种数据库的普通索引，并必须在实施计划中列出迁移与回退步骤。

## 14. 测试与验证策略

### 14.1 后端

使用确定性固定数据验证：

- 默认只返回 `active`；
- 状态为“全部”时返回活动、草稿和已退休版本；
- 渠道、模型包含匹配、成本模式、状态、币种和来源筛选；
- 组合筛选、白名单排序、稳定分页和越界参数拒绝；
- 渠道、币种和来源 facets 完整且不随当前筛选缩减；
- 渠道左连接和已删除渠道降级；
- 摘要应用非状态筛选并忽略状态筛选；
- 四种成本模式和三个 Token 子模式的价格项投影；
- 按次完整成本保持不变，15 秒等效值仅出现在比较字段；
- 无效配置返回 `price_status=unavailable` 和问题代码而不是 `$0` 或整页失败；
- 详情返回正确业务键的版本历史；
- 无权限管理员和普通用户不能读取目录。

关键查询必须在 SQLite 测试中覆盖，并通过项目已有 MySQL、PostgreSQL 测试路径或等价集成检查验证方言兼容性。

### 14.2 CSV

- `filtered` 与列表使用相同筛选条件且忽略分页；
- `all` 忽略筛选并包含所有状态；
- 列顺序、表头和行数稳定；
- UTF-8 BOM、中文、逗号、引号和换行正确；
- `= + - @` 和前导空白公式注入被中和；
- 未知价格不写成零；
- 15 秒等效列明确标记“仅比较”；
- 凭据、Base URL、渠道扩展配置和原始 JSON 不存在于文件中；
- 超限在文件响应开始前失败。

### 14.3 前端

- `tab=catalog` 显示目录，其他 Tab 不请求目录；
- URL 筛选、排序、页码可恢复并与利润参数隔离；
- 默认活动规则、清除筛选和切换筛选回到第一页；
- 加载、刷新、空目录、筛选无结果和错误重试状态；
- 桌面固定列和移动展开项的主要信息；
- 未知值不显示为 `$0`；
- 详情抽屉内容、失败重试和焦点恢复；
- 当前结果与全部导出的参数范围；
- 键盘操作、可访问名称和排序语义。

## 15. 兼容性、迁移与回退

本设计不修改现有成本规则结构和结算事实，不需要数据迁移。新 API 为新增接口，现有 `/rules`、利润报表、异常和成本详情合同保持不变。

前端 Tab 参数新增 `catalog`，旧 URL 未指定 Tab 时仍进入 `profit`。目录专用查询参数使用前缀，不改变已有利润报表 URL 语义。

回退时可删除第三个 Tab、新增目录组件和三个只读路由；已有规则、渠道、结算、导入批次和历史数据不受影响。若实施阶段增加普通索引，回退需在计划中提供三种数据库对应的安全删除方式。

## 16. 验收标准

1. 具备 `cost_accounting.read` 的管理员可从成本核算页进入“供应商成本目录”；
2. 首版页面没有创建、编辑、激活或退休入口；
3. 管理员可按六个维度筛选，并通过 URL 恢复当前视图；
4. 页面完整展示所有成本模式的原币价格、标准化 USD 价格和计费单位；
5. 无效或缺失成本显示为未知或不可用，绝不显示为零；
6. 按次规则的完整成本继续用于结算和严格路由，15 秒等效秒价只用于人工比较；
7. 详情抽屉展示完整换算参数、备注、有效期和版本历史；
8. 当前筛选导出与页面查询口径一致，全量导出包含所有状态；
9. CSV 可由 Excel 正确打开，抵御公式注入且不包含渠道凭据；
10. 查询兼容 SQLite、MySQL 和 PostgreSQL，并且没有 N+1；
11. 普通用户和缺少权限的管理员无法读取目录接口；
12. 后端、前端、构建、E2E 和严格模式回归全部通过。

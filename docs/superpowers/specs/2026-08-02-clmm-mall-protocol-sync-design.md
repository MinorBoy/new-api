# CLMM Mall 渠道协议同步设计

## 1. 背景

`docs/new-channels/cn-clmm.md` 是 CLMM Mall 创建视频任务与查询视频任务的 API 接入文档。模型目录本身不由该文档维护，正确的完整模型 ID 仍以 SD 收录表或渠道模板表的导入结果为准。

CLMM Mall 的特殊之处在于：导入的完整模型 ID 同时携带渠道前缀和协议控制后缀。适配器必须解释这些控制信息，才能正确生成 `seconds`、`mySeconds`、分辨率和参考素材字段。模型来源与模型协议解释是两个不同职责，不能因为模型 ID 来自导入配置而删除后缀解析。

当前实现已经支持主要前缀和 `-Ns`、`-gz`、`-Nimg`、`-nv` 控制规则，但与最新版文档仍有以下差异：

- 文档调整时误删了模型前缀、控制后缀和 `mySeconds` 规则；
- 上游请求 DTO 没有 `reference_audios`，Ark 音频输入会被本地拒绝；
- 路由契约禁止 CLMM target 声明音频能力，与渠道模板中已导入的音频限制不一致；
- 创建任务失败后，控制器可能按通用任务策略切换渠道重试，存在重复创建收费任务的风险。

## 2. 目标

1. 恢复 `cn-clmm.md` 中决定上游传参所必需的渠道前缀、控制后缀和 `mySeconds` 规则。
2. 明确模型 ID 的唯一目录来源仍是 SD 收录表或渠道模板表，文档和代码不维护具体基础模型白名单。
3. 保留现有后缀解析和实际时长计费逻辑。
4. 支持最新版协议声明的 `reference_audios` 字段。
5. 禁止 CLMM 创建任务自动重试，避免产生重复任务和重复成本。
6. 保持公共任务 ID 隔离、查询状态映射、结果 URL 优先级、结算和退款行为不变。

## 3. 非目标

- 不修改 SD 收录表或渠道模板表中的模型、能力和价格数据。
- 不从 `/api/pricing` 动态覆盖导入配置。
- 不在代码中枚举渠道前缀之后的具体基础模型名。
- 不把控制后缀拆成新的数据库列或配置导入字段。
- 不改变 Ark 客户端 API、公共模型名或任务响应结构。
- 不支持 Ark 未提供的 `persist` 入站字段。
- 不修改 CLMM 查询任务的重试和轮询调度策略。

## 4. 真相源边界

### 4.1 模型目录与商业数据

SD 收录表或渠道模板表的导入结果负责定义：

- 可用的完整上游模型 ID；
- 客户端模型到上游模型的映射；
- 路由能力，包括时长、分辨率和参考素材数量；
- 成本模式、价格、币种和汇率。

CLMM 适配器不维护这些数据的第二份副本。

### 4.2 CLMM 协议控制信息

适配器负责解释导入后的完整模型 ID 中已定义的协议控制信息：

- 渠道前缀：`sh-`、`grok-`、`veo-`、`bbv3-`、`bbv4-`、`me-`、`hj-`、`mowc-`、`op-`；
- 分辨率段：`-480p`、`-480P`、`-720p`、`-720P`；
- 时长段：`-{n}s`；
- 固定时长段：独立的 `-gz`；
- 最少图片段：`-{n}img`；
- 禁用参考视频段：独立的 `-nv`。

前缀用于确认该字符串符合 CLMM 完整模型 ID 的基本语法，不对前缀后的基础模型名设置本地白名单。`-sr`、`-nsp`、`-nyp`、`-nyy` 等未定义字符串继续作为基础模型名的一部分，不产生本地行为。

## 5. 请求转换

### 5.1 字段映射

| Ark 入站 | CLMM Mall 上游 | 规则 |
|---|---|---|
| 映射后的完整模型 ID | `model` | 原样发送完整模型 ID |
| 文本内容 | `prompt` | 按 content 顺序用换行连接非空文本 |
| `ratio` | `aspect_ratio` | 继续支持 `16:9`、`9:16` |
| `resolution` | `resolution` | 缺省 `480p`，模型分辨率控制段优先 |
| 比例 | `size` | `16:9` 使用 `1280x720`，`9:16` 使用 `720x1280` |
| 图片内容 | `reference_image_urls` | 保持输入顺序 |
| 视频内容 | `reference_videos` | 保持输入顺序，模型含 `-nv` 时丢弃 |
| 音频内容 | `reference_audios` | 保持输入顺序 |
| `duration` | `seconds` / `mySeconds` | 按模型时长控制段转换 |

`model` 必须原样发送导入后的完整模型 ID。控制段只用于计算请求字段，不从发送给 CLMM Mall 的 `model` 中删除。

### 5.2 时长规则

继续按以下顺序计算渠道实际时长和计费时长：

1. 模型含独立 `-gz` 时必须同时含 `-{n}s`，否则返回 `400`。
2. 模型同时含 `-gz` 和 `-{n}s` 时，发送 `seconds="1"`、`mySeconds="n"`，忽略 Ark 中不同的有效 `duration`，实际时长和计费时长均为 n。
3. 模型不含 `-gz`、但含 `-{n}s` 时，发送 `seconds="1"`。Ark 未传 `duration` 时 `mySeconds="n"`；已传时必须为正整数且不超过 n，并把该值发送为 `mySeconds`。实际时长和计费时长均使用最终 `mySeconds`。
4. 模型既不含 `-gz` 也不含 `-{n}s` 时，不发送 `mySeconds`，把 Ark `duration` 或默认值作为 `seconds`、实际时长和计费时长。
5. 所有最终时长继续受 `relaycommon.MaxTaskDurationSeconds` 和普通模型 5 到 15 秒边界保护。

### 5.3 参考音频

Ark `audio_url` 仅接受空 role 或 `reference_audio`，URL 必须非空。转换后写入 `reference_audios` 并保持原顺序。

协议级全局上限采用图片 9 张、视频 3 个、音频 3 个、素材总数 12 个。导入 route target 可以声明更严格的图片、视频和音频上下限；渠道选择阶段继续依据这些约束过滤不兼容请求。

`-Nimg` 和 `-nv` 仍由适配器执行，因为它们直接改变上游请求语义。音频能力不根据模型名新增推导规则，只以导入 route target 和协议全局上限为准。

## 6. 路由契约

CLMM route target 验证继续要求：

- 完整上游模型 ID 通过 CLMM 前缀和控制后缀语法校验；
- 输出分辨率只声明适配器可表达的 `480p`、`720p`；
- 普通模型的时长在 5 到 15 秒范围内；
- 带 `-{n}s` 控制段的模型由控制段约束实际时长；
- 图片、视频、音频上限分别不超过 9、3、3，合计不超过 12；
- 参考素材最低数量不能超过对应上限。

这项验证不检查具体基础模型名，也不修改导入的模型 ID、能力或成本数据。

## 7. 创建请求重试

CLMM 创建任务一旦进入上游提交阶段，任何 `429`、`5xx`、连接中断、超时或其他结果不确定错误都不得自动切换渠道重新调用 `POST /v1/videos`。

控制器的任务重试判断增加 CLMM task-only 渠道策略，并在通用状态码判断之前返回“不重试”。本地路由选择、成本覆盖等尚未发送创建请求的前置失败仍可按现有策略选择其他兼容渠道，因为这些失败不会产生上游任务。

查询任务继续使用现有调度器。临时网络错误和 `429`、`500`、`502`、`503` 仍保持可重试，不受创建请求策略影响。

## 8. 错误处理

- `400`、`422` 继续映射为稳定的请求参数错误。
- `429` 继续映射为稳定的限流错误，但创建请求不自动重试。
- `402`、`403` 保留无自动重试语义，并返回不包含上游凭据、私有任务 ID或原始诊断信息的稳定错误。
- 其他上游错误继续映射为清理过的网关错误。
- 查询失败和任务终态错误继续保留现有公共错误投影，禁止泄露上游 API Key、私有任务 ID、渠道 ID和原始响应。

## 9. 计费与任务生命周期

- `arkToClmm` 返回的实际时长继续作为预扣和最终计费时长。
- 普通、可缩短 `-{n}s` 和固定 `-gz` 模型不得使用占位值 `1` 计费。
- 音频数量不作为计费乘数，不引入新的比例字段。
- 创建请求不重试，避免同一公共请求关联多个未知上游成本。
- 公共任务 ID、私有上游任务 ID、任务落库、终态结算和退款继续复用现有共享流程。

## 10. 测试设计

### 10.1 模型控制规则

- 保留普通、可缩短 `-{n}s`、固定 `-gz`、`-Nimg` 和 `-nv` 的精确请求测试。
- 增加任意合法前缀后基础模型名通过的测试，证明没有具体模型白名单。
- 保留缺失前缀、`-gz` 缺少时长、冲突时长、超限时长和非法图片数量失败测试。
- 断言完整模型 ID 原样发送给 CLMM Mall。

### 10.2 音频

- 断言 Ark 音频按输入顺序转换为 `reference_audios`。
- 断言空 URL和非法 role 返回 `400`。
- 断言 3 个音频和总计 12 个素材的边界通过，超出边界失败。
- 断言 route target 可以声明音频能力，超过协议上限时失败。

### 10.3 创建重试

- CLMM 创建返回 `429` 时只调用一次上游。
- CLMM 创建返回 `500` 时只调用一次上游。
- CLMM 创建发生结果不确定错误时不切换渠道。
- 其他既有允许重试的 task channel 行为保持不变。

### 10.4 回归验证

- CLMM adaptor、路由契约和控制器 focused tests。
- Ark 创建、单查、列表、公共任务 ID隔离和计费测试。
- 配置导入测试，确认已导入的 CLMM 音频能力不再被路由契约拒绝。

## 11. 验收标准

1. 文档同时说明模型 ID 来源和模型 ID 控制段解释规则，二者不再混淆。
2. 普通、可缩短和固定时长模型生成正确的 `seconds`、`mySeconds` 和计费时长。
3. CLMM 支持导入 route target 允许的参考音频请求。
4. 创建任务在任何上游错误下最多调用一次 CLMM。
5. 查询重试、结果 URL优先级和公共任务响应保持兼容。
6. 相关 Go 测试、配置导入测试和文档结构检查通过。

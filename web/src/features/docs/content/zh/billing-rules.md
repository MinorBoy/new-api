# 计费规则

本页说明 new-api 的计费机制、缓存折扣与失败处理策略。

## 计费公式

对话类模型按 Token 计费，总额度的计算方式为：

```
消耗 = 输入Token × 输入倍率 + 输出Token × 输出倍率
```

- **输入（Prompt）Token 与输出（Completion）Token 分别计价**，输出通常更贵。
- 倍率以 [模型广场](/pricing) 的实时展示为准。

图像、视频、语音等模型若标注「按次计费」，则按每次请求固定扣费，与 Token 无关。

## 预扣费与结算

为防止额度透支，每次请求采用**两阶段扣费**：

1. **预扣费**：请求开始前，按预估消耗上限预先冻结额度。若额度不足以覆盖预估消耗，请求直接失败并返回 `pre_consume_token_quota_failed` / `insufficient_user_quota`。
2. **结算**：请求完成后，按实际消耗多退少补。

## 失败不扣费

以下情况**不会扣费**：

- 请求在到达上游前失败（鉴权失败、模型不存在等）。
- 上游返回非 2xx 状态码（`bad_response_status_code`、`do_request_failed` 等）。
- 内部 `5xx` 错误。

预扣费会在结算阶段全额退还。只有成功完成并返回有效响应的请求才会计入扣费。

## 缓存折扣

部分上游支持 **Prompt 缓存**（如 Anthropic 的 prompt caching）：

- 命中缓存的输入 Token 享受更低的缓存倍率。
- 创建缓存（首次写入）可能产生一次额外的缓存创建费用。
- 具体折扣比例见 [模型广场](/pricing) 各模型详情。

缓存命中率越高，单次请求成本越低。建议对包含大量固定上下文（系统提示、长文档）的请求启用缓存。

## 分组倍率

管理员可为不同用户分组配置不同的折扣倍率。你在 [模型广场](/pricing) 切换分组时，看到的价格会相应变化。

## 速率限制

每个 API Key 默认受以下限制（具体阈值由管理员配置，可在「**令牌**」编辑页查看）：

- 单位时间内的请求数。
- 单位时间内的成功请求数。
- 单位时间内的 Token 总量。

超过限制时返回 `429`，错误信息会提示已达到的限制类型。额度不足返回 `insufficient_user_quota`，速率限制返回相应提示，二者不同。

## 下一步

- 遇到扣费疑问，对照 [错误码参考](/docs/error-codes) 排查。
- 想降低成本？查看 [模型与计费](/docs/pricing) 选择性价比更高的模型。

# Ark 视频合同阻断根治设计

## 背景

2026-08-04 Ark SDK 视频素材矩阵 E2E 共发布 155 个路由目标，其中 36 条在渠道合同校验阶段被阻断。阻断分布为 Cangyuan 12、CLMM 18、8yes 1、MegaByAI 4、Secure 企业组 1。所有阻断均发生在上游调用和计费前，因此没有形成任务、使用日志或成本流水。

逐条调用真实 `relay.ValidateVideoRouteTargetContract` 后，36 条阻断可分为两类：

- 协议或模板实现缺陷 19 条：CLMM 18 条模型合同误拒绝，Secure 1 条渠道级时长被公共 SKU 覆盖。
- 源表与已验证供应商合同冲突 17 条：Cangyuan 12 条媒体素材声明、8yes 1 条模型与分辨率冲突、MegaByAI 4 条不受支持分辨率。

本次根治不能通过放宽真实渠道协议或继续兼容错误的公共 SKU 时长完成。项目尚未上线，错误价格和能力应在源头删除或修正，模板生成阶段必须阻止同类冲突再次进入导入配置。

## 目标

- CLMM 接受源表中的真实上游模型 ID，同时继续解析已验证的模型控制段。
- CLMM 普通模型允许显式 4 至 15 秒请求，默认时长仍为 5 秒。
- 渠道级时长独立保存在模型映射和 route target 中，不再由公共 SKU 覆盖。
- 单值时长如 `15` 被解释为精确的 `15-15`，而不是隐含范围。
- 公共 SKU 汇总全部来源行的总体时长能力，不再由首行决定。
- 修正 Cangyuan、8yes、MegaByAI 的明确源数据冲突。
- 在模板生成或导入前执行渠道合同门禁，已知合同冲突不得发布为活动路由。
- 重生成模板和 JSON 配置，导入本地系统并将 E2E 合同阻断降为 0。

## 非目标

- 不为缺少供应商证据的能力放宽渠道协议。
- 不改变 Ark SDK 客户端请求格式。
- 不改变 Seedance 用户售价、供应商成本或利润计算公式。
- 不保留已确认错误的旧“渠道 + 模型价格”兼容分支。
- 不回写既有 E2E 日志；重新运行后生成新的验收数据。

## 根因与处理

### CLMM 18 条

`relay/channel/task/clmmmall/translate.go` 使用固定前缀白名单判断模型是否合法，只接受 `sh-`、`grok-`、`veo-`、`bbv3-`、`bbv4-`、`me-`、`hj-`、`mowc-`、`op-`。最新源表中的 `mg-seedance...`、`ov-Seedance...`、`seedance2.0...` 因此在合同校验阶段被误拒绝。

CLMM 文档要求上游模型 ID 以 SD 收录表和渠道模板为准，适配器只需要识别追加在模型 ID 后的控制段。固定基础模型白名单既不属于供应商合同，又会在每次新增模型时制造阻断。

处理方式：删除基础模型前缀白名单，保留完整上游模型 ID；从末尾识别 `480p`、`720p`、`Ns`、`gz`、`Nimg`、`nv` 控制段。控制段按连字符和空白边界解析，以兼容模型 ID 自身包含空格。路由合同与实际提交共用同一个模型分析结果，不再维护重复的 `clmmModelControlsDuration` 判断。

### Secure 企业组 1 条

源表 `sd!69` 声明 `5-15` 秒，但生成 route 变成 `4-15`。模板生成器以 `canonical model + version + resolution` 去重公共 SKU，首个来源行通过 `rows.has(id)` 胜出。转换器随后从公共 SKU 读取时长并复制给所有渠道映射，导致 Secure 自身的 `5-15` 被其他渠道的 `4-15` 覆盖。

处理方式：公共 SKU 只表示模型总体能力；每条模型映射显式保存 `duration_min` 和 `duration_max`。V1 模板“模型映射”工作表增加结构化时长列，转换器从映射生成 route target 时读取这些列。公共 SKU 的总体时长范围使用所有来源行的最小值和最大值聚合，仅用于目录能力展示，不作为渠道合同来源。

### Cangyuan 12 条

源表 12 行声明素材码 `933` 和 `omni_reference`，但现有 Cangyuan 文档与适配器只支持纯文本 JSON 字段 `model`、`prompt`、`aspect_ratio`、`duration`，没有图片、视频或音频上传协议证据。

处理方式：将这些来源行修正为素材码 `000`、输入模式 `text`。不得通过适配器静默丢弃媒体或放宽合同。

### 8yes 1 条

源表 `sd!64` 使用模型 `videos-mini-480p`，分辨率列却声明 `720p`，模型名和能力声明互相冲突。

处理方式：以该价格行实际分辨率为准修正为一致的模型和分辨率组合；若没有独立 720p 供应商证据，则保留 `videos-mini-480p + 480p`。

### MegaByAI 4 条

源表 `sd!108`、`sd!109`、`sd!124`、`sd!125` 声明 `1080p` 或 `4k`，但已验证渠道文档仅支持 `480p` 和 `720p`。

处理方式：彻底删除这四条不受支持价格/能力行，不做分辨率降级、别名映射或兼容保留。

## 数据模型

V1 模板“模型映射”增加：

| 字段 | 含义 |
| --- | --- |
| `最小时长秒` | 当前渠道线路和上游模型组合允许的最小时长 |
| `最大时长秒` | 当前渠道线路和上游模型组合允许的最大时长 |

生成器内部的映射记录同步增加 `durationMin` 和 `durationMax`。写入模板时生成结构化列；V1 适配器读取后保存在 extracted mapping 字段中；文档转换器从 mapping 生成 route target 的 `duration_min` 和 `duration_max`。

公共 SKU 仍保留总体 `duration_min` 和 `duration_max`，但其值是所有映射能力的并集边界。route target 不允许再从公共 SKU 继承时长。

## CLMM 模型控制解析

模型分析器返回基础模型和控制结果。解析按模型字符串末尾向前执行，只消费完整控制段：

- `480p`、`720p`：覆盖请求分辨率。
- `Ns`：设置最大或固定时长，沿用现有控制语义。
- `gz`：沿用现有固定时长语义。
- `Nimg`：设置最少参考图片数。
- `nv`：丢弃参考视频，沿用已验证协议行为。

未识别的片段属于基础模型 ID，不构成拒绝理由。空模型、只有控制段而没有基础模型、非法控制值仍返回明确错误。

普通模型的显式时长范围改为 4 至 15 秒；未传时长时继续使用 5 秒。控制模型继续按控制段限制执行。

## 生成门禁

生成器在输出模板前对已知渠道调用与后端合同等价的静态规则：

- 分辨率必须属于渠道已验证集合。
- 模型必须满足渠道模型语法，而不是固定模型枚举。
- 渠道映射的时长范围必须落在渠道合同内。
- 素材最小值、最大值、总量和输入模式必须与渠道协议一致。

错误为阻断级问题，生成命令即使使用 `--allow-warnings` 也不得忽略。警告只用于缺少非关键商业字段，不能覆盖合同冲突。

## 测试策略

### Go 单元测试

- CLMM 真实模型 ID `mg-seedance...`、`ov-Seedance...`、`seedance2.0...` 通过模型合同。
- 包含空格的模型 ID 仍可识别尾部控制段。
- 普通 CLMM 模型显式 4 秒成功，3 秒和 16 秒失败。
- 路由合同与提交转换共用模型分析结果，受控时长模型不被普通范围误拒绝。

### 模板生成测试

- `parseDuration("15")` 生成 `15-15`。
- 同一公共 SKU 的多条来源映射保留各自时长。
- 公共 SKU 总体范围按来源行聚合。
- 模型映射工作表写出结构化时长列。
- 已知渠道合同冲突在生成阶段形成 error。

### 转换器测试

- V1 适配器读取模型映射的结构化时长列。
- route target 从 mapping 读取时长，不从 SKU 继承。
- Secure 映射保持 `5-15`，即使公共 SKU 总体范围为 `4-15`。

### E2E

- 重生成后的全部活动 route target 通过 `ValidateVideoRouteTargetContract`。
- 合同阻断从 36 降为 0。
- 成功、失败、禁用价格和素材限制用例按新模板精确统计。
- 任务详情继续满足完整 Ark 终态响应合同。
- 使用日志、任务日志、成本核算和利润数据完整生成。

## 验收标准

- Cangyuan、CLMM、8yes、MegaByAI、Secure 不再产生上述 36 条合同阻断。
- 修正后的源表、模板和 JSON 配置可重复生成，结果稳定。
- 本地导入后活动渠道和模型映射与模板一致。
- 完整 Ark 视频矩阵 E2E 无合同阻断，并生成新的日志、任务和成本数据。
- Go 测试、前端定向测试、类型检查、构建和 `git diff --check` 全部通过。

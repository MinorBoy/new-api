# 刷新 SD 渠道配置

把最新版 `sd收录` 作为唯一业务事实来源，完成“下载 -> 校验 -> 生成 -> 转换 -> 导入 -> 激活 -> E2E -> 报告”的闭环。每个阶段都保留哈希、计数、问题和运行证据；前一阶段未通过时不得推进下一阶段。

## 必须使用的能力

- **REQUIRED SUB-SKILL:** 使用 `chrome:control-chrome` 操作用户已有 Chrome 登录态；如果目标表格位于应用内浏览器，则使用 `browser:control-in-app-browser`。只控制包含目标 Google 表格或本地 new-api 的相关标签页。
- **REQUIRED SUB-SKILL:** 使用 `spreadsheets:Spreadsheets` 读取、检查、重算、渲染和验证源表及生成模板。
- **REQUIRED SUB-SKILL:** 完成前使用 `superpowers:verification-before-completion`，以最新命令输出为准。
- 修改生成器、转换器或 E2E 代码时，先使用 `superpowers:brainstorming` 和 `superpowers:test-driven-development`；不要为赶进度跳过设计或失败测试。

开始前读取仓库 `AGENTS.md`、`docs/channel-model-template-generator.md`，并按需读取 [项目流程合同](references/project-workflow.md)。

## 工作流

### 1. 建立基线

1. 检查工作树和本地服务状态，保留用户已有修改。
2. 记录仓库源表 SHA-256、当前已发布/已激活批次、成本核算模式、全局最低毛利率和相关分组倍率。
3. 创建本轮输出目录，并定义源表、模板、导入 JSON、问题报告、E2E 日志和验收报告路径。
4. 未明确要求真实上游时，把本轮 E2E 定义为 Mock 上游完整链路；不得擅自产生供应商费用。

### 2. 下载最新源表

1. 在已登录标签页打开固定表格，确认标题和表格 ID 完全一致。
2. 使用 Google 表格“下载 -> Microsoft Excel (.xlsx)”；用下载前后文件列表、修改时间和 SHA-256 确认实际新文件，不按猜测文件名取文件。
3. 将下载文件复制到本轮输出目录为 `sd收录.xlsx`，保留原下载文件。
4. 不读取或引用其他浏览器标签页；URL、Cookie、Token 和 API Key 不得写入终端输出、报告或仓库。

若登录失效，停在本阶段请用户登录；登录完成后从同一阶段继续。

### 3. 校验源表

使用电子表格技能完成以下门禁：

1. 确认存在 `channel`、`sd`、`sd官价`，记录实际范围、表头和有效行数。
2. 检查公式错误，至少覆盖 `#REF!`、`#DIV/0!`、`#VALUE!`、`#NAME?`、`#N/A`。
3. 检查关键业务字段：渠道、模型 ID、计费方式、单价、清晰度、时长、素材限制、状态、官方价格。
4. 渲染并目视检查每个工作表，确认标题、数字、公式和备注没有截断或异常空白。
5. 比较仓库源表哈希；若内容相同，仍可验证和跑 E2E，但不得创建重复发布批次。

源表结构变化时，以新表的明确业务语义为准。生成器不兼容时停止发布，先按测试驱动扩展兼容性；不要把新列手工改回旧表头，也不要猜测价格单位。

### 4. 生成并复核模板

1. 从本轮输出目录的已验证源表生成模板，不先覆盖仓库源表。
2. 使用项目既有 `channel-model-template:generate` 命令和版本化规则文件。
3. 审阅 JSON 报告：任何 `FAIL` 都必须阻止模板导入；每个 `WARN` 和 `draft` 必须说明原因、影响和处理决定。
4. 用电子表格技能检查生成模板全部工作表、公式和视觉结果。
5. 对“利润测算”至少抽查三种成本模式：
   - `per_request` 使用完整按次成本，不按实际秒数摊薄供应商成本；
   - `per_duration` 使用每秒成本乘输出计费秒数；
   - `per_token` 使用标准 Token 单价和估算 Token；
   - 毛利率为 `(用户收入 - 渠道成本) / 用户收入`，收入为零时留空；
   - 分组倍率只影响用户收入，不改变供应商成本。
6. 模板和报告通过后，才把本轮 `sd收录.xlsx` 更新为仓库源表，并记录更新后的哈希。

### 5. 转换并导入

1. 打开本地 `/config-import`，通过“Excel 转换”上传已验证模板。
2. 选择本轮要维护的渠道线路；默认纳入所有已存在、类型匹配且已经配置凭据的真实渠道。缺少凭据或匹配歧义的线路保持跳过，不创建、覆盖或输出 API Key。
3. 下载“选中配置 JSON”到本轮输出目录，并保存问题报告；该 JSON 同时作为导入证据和 E2E 数据源。
4. 导入配置后按现有状态机完成：绑定渠道并暂存 -> 解决冲突并重新暂存 -> 定价审阅并重新暂存 -> 路由差异审阅 -> 校验 -> 发布 -> 激活。
5. 只对本批次拥有且通过预检的渠道、规则、策略和目标执行激活。发布不等于启用；存在激活 blocker 时不得绕过。
6. 记录批次 ID、状态、实体计数、绑定结果、问题、退休目标数、新启用目标数和缓存刷新结果。

绑定必须核对渠道类型、Base URL、渠道分组和专属设置，不能只按显示名称匹配。Secure 多线路必须核对 `secure_video_group`。

### 6. 执行一轮 E2E

默认执行 Mock 上游 Ark SDK 视频素材矩阵完整链路，并使用本轮导出的选中配置 JSON：

1. 先运行配置转换器与模板 focused tests。
2. 将选中配置 JSON 作为本轮 E2E fixture；更新仓库 fixture 前检查实体计数和语义差异。
3. 运行 `TestSeedanceImportedMaterialMatrixFullFlowE2E`，覆盖导入配置、能力合同、路由、Ark 提交/查询、任务日志、使用日志、供应商成本和利润核算。
4. 用户明确要求写入本地运行库时，再执行既有 `ark-video-material-seed`；执行前记录运行时设置，完成或失败后都恢复原成本模式、最低毛利率和分组倍率。
5. 只有用户明确要求“真实上游”时才运行真实 Canary；固定具体渠道、限制预算、串行执行，并跳过已有成功证据的目标。

E2E 失败时保留首个失败、目标、请求阶段和日志位置，不把失败目标标记为通过，也不继续真实上游测试。

### 7. 产出验收报告

在本轮输出目录生成简体中文验收报告，至少包含：

- 源表、模板、报告和选中 JSON 的绝对路径及 SHA-256；
- 模板各工作表行数、`FAIL`/`WARN`/`draft` 数和利润抽查结果；
- 批次 ID、状态、绑定、发布、激活和目标退休/启用计数；
- E2E 命令、退出码、任务/日志/成本/利润结果和异常；
- 运行时设置恢复结果、未覆盖项和下一步。

释放本轮占用的浏览器标签页。除非用户明确要求，不提交输出目录中的下载物、凭据或运行日志。

## 停止条件

遇到以下任一情况立即停止后续发布或 E2E，并报告可复现证据：

- 下载文件身份无法确认或工作表缺失；
- 源表/模板存在公式错误、生成报告 `FAIL` 或无法解释的价格单位；
- 导入 JSON 存在 error，或线路无法唯一绑定到已有真实渠道；
- 定价、素材合同、成本覆盖或路由审阅存在未解决 blocker；
- 发布失败、激活预检未通过或缓存状态不确定；
- E2E 将访问真实上游但用户未授权。

## 常见错误

| 错误做法 | 正确处理 |
| --- | --- |
| 直接覆盖仓库源表后才发现下载错误 | 先在唯一输出目录校验，模板通过后再更新源表 |
| 为兼容生成器手工改回旧表头 | 以新表语义为准，测试驱动扩展解析器 |
| `--allow-warnings` 后忽略 draft | 逐项说明并确保 draft 不会激活 |
| 只按渠道名称绑定 | 同时核对类型、Base URL、分组、专属设置和凭据存在性 |
| 发布后默认已经接流量 | 检查并执行独立激活步骤 |
| 按次成本除以 15 秒后按短时长结算 | 路由和利润使用完整按次成本；折算仅用于横向比较 |
| E2E 改写严格模式后不恢复 | 前置快照，成功或失败都恢复并复核 |
| 把 Mock 成功描述为真实上游成功 | 报告明确区分 Mock、真实本地代码和真实供应商请求 |

# 成本利润颜色与任务结果审计设计

## 目标

成本核算页面中的“计费毛利润”和“毛利率”按数值正负显示语义颜色：正数使用成功色，负数使用危险色，零值和不可用值保持中性色。

任务日志的“任务详情”展示异步任务最终返回给用户的公开结果。E2E 持久化数据同时包含成功和失败 mock，且不得暴露上游任务 ID、渠道内部字段、密钥或签名参数。

## 数据链路

异步轮询把任务推进到 `SUCCESS` 或 `FAILURE` 后，根据任务提交时保存的 `request_path` 选择公开响应协议：

- `/v1/video/generations`、`/v1/videos` 使用 OpenAI Video 响应转换器。
- `/api/v3/contents/generations/tasks` 使用 ARK 视频响应转换器。
- 其他未定义协议不生成推测响应，保留现有按用户查询时归档的行为。

转换完成的响应通过现有 `TaskPrivateData.UserResponseData` 持久化。该字段仅在管理员任务日志 API 中返回，普通用户任务列表继续隐藏。

## E2E 数据

渠道素材矩阵的 110 条成功任务保持不变。seed 在矩阵完成后额外提交一条可识别的失败 mock 任务，经真实提交、轮询、退款和成本结算链路进入终态。成功任务和失败任务都必须具有 `user_response_data`，并通过公开字段断言防止内部数据泄露。

## 前端

正负值判断直接解析后端返回的规范整数字符串，不使用格式化后的展示文本：

- `> 0`：`text-success`
- `< 0`：`text-destructive`
- `= 0`、缺失或非法值：不附加语义颜色

覆盖利润汇总、渠道模型利润表和单次成本请求详情三个位置。

## 验证

- 前端组件测试覆盖正数、负数和零值颜色。
- 服务轮询测试覆盖成功与失败终态响应持久化。
- NewAPIVideo E2E 覆盖公开成功/失败响应及私有字段隔离。
- seed 单元测试覆盖成功与失败 mock 响应。
- 重跑持久化 seed 后核对任务状态、终态结果数量及页面数据。

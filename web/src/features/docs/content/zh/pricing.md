# 模型与计费

new-api 支持 40+ 上游服务商的数百个模型。完整的**实时**模型清单、分组可用性与价格，请前往 [模型广场](/pricing) 查看。

## 计费方式概览

每个模型按以下维度计费，具体倍率以模型广场的实时展示为准：

- **按 Token 计费**：输入（Prompt）Token 与输出（Completion）Token 分别计价。
- **按次计费**：部分图像、视频、音频模型按「每次请求」固定价格计费。
- **分组倍率**：不同用户分组可应用不同折扣倍率，在模型广场顶部切换分组查看。

## 缓存计费

部分上游支持 **Prompt 缓存**（如 OpenAI GPT-5 系列的缓存读取、Anthropic prompt caching、Gemini 上下文缓存）。命中缓存可显著降低重复上下文的成本。

### 三种 Token 的计费差异

一次请求的输入 token 会被拆分为三部分，分别按不同倍率计费：

| Token 类型 | 说明 | 计费倍率 |
|---|---|---|
| **缓存读取**（cached_tokens） | 命中上游缓存的输入 token，例如重复的系统提示、长文档前缀 | **缓存读取倍率**（cache_ratio），通常远低于输入倍率（如 0.5） |
| **缓存创建** | 首次写入缓存时额外计费的 token（部分上游支持，如 Anthropic） | **缓存创建倍率**（create_cache_ratio），通常略高于输入倍率（如 1.25） |
| **未命中输入** | 未命中缓存的常规输入 token | 正常**输入倍率** |

> 倍率含义：以 0.5 的缓存读取倍率为例，命中缓存的 token 只按正常输入价格的 50% 计费。

### 命中缓存的示例

以 `gpt-5.6-sol` 为例，假设一次请求：

- 输入共 10000 token，其中 **8000 token 命中缓存**（系统提示 + 历史对话前缀重复）
- 输出 500 token
- 缓存读取倍率 0.5，输入倍率 1.0，输出倍率 4.0

```
费用 = 8000 × 0.5  (缓存读取)
     + 2000 × 1.0  (未命中输入)
     + 500  × 4.0  (输出)
     = 8000
```

若不启用缓存，10000 token 全按输入倍率计费 = 10000，**缓存节省了 20%**。上下文越长、重复度越高，节省越明显。

### 如何查看缓存倍率

每个模型的缓存倍率显示在 [模型广场](/pricing) 对应卡片详情中。模型卡片展开后会标注：

- 是否支持缓存（`cache_ratio` 字段存在即支持）
- 缓存读取倍率（`cache_ratio`）
- 缓存创建倍率（`create_cache_ratio`，仅部分模型）

未显示缓存倍率的模型不支持 Prompt 缓存，所有输入 token 按正常输入倍率计费。

### 启用缓存

调用方通常**无需额外操作**——只要上游模型支持缓存，重复的前缀上下文会自动命中。建议：

- 将**固定内容**（系统提示、工具定义、长文档）放在 `messages` 数组**开头**，变动内容放后面，以提高缓存命中率。
- 对 Anthropic 模型，可在请求中显式使用 `cache_control` 标记需缓存的块。

详见 [计费规则](/docs/billing-rules) 了解预扣费、结算与失败不扣费机制。

## 如何查看价格

1. 打开 [模型广场](/pricing)。
2. 在顶部切换你的用户分组（如默认分组）。
3. 每张模型卡片显示：
   - 输入价格（每百万 token）
   - 输出价格（每百万 token）
   - 上下文窗口、能力标签
   - 支持的接口端点

点击任意模型卡片可展开详细的计费明细、调用示例与支持的参数。

## 计费单位

- Token 计价的模型，额度按「输入 token × 输入倍率 + 输出 token × 输出倍率」折算。
- 价格单位为人民币元（CNY），1 元 = 500000 额度单位（具体以系统配置为准）。

## 分组与可用性

并非所有模型对所有分组开放。若某个模型在模型广场显示「不可用」，可能是：

- 当前分组未配置该模型的上游渠道。
- 你的账号分组未开放该模型权限。

联系管理员可调整分组配置。详见 [计费规则](/docs/billing-rules) 了解计费、缓存折扣与失败不扣费策略。

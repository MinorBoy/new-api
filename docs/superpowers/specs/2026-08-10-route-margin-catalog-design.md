# 路由毛利目录设计

## 背景

当前“成本核算 -> 供应商成本目录”只能按渠道、模型、成本模式、状态、货币和来源筛选成本规则，不能按路由目标的预计毛利率筛选。此前的“全局毛利率 30% 路由目标统计”使用 4 秒输出、默认分组倍率以及 `no_video`/`with_video` 场景，统计出至少一个场景达标的 75 个目标，但该口径尚未在页面中提供可交互查询。

毛利率不是静态成本属性：按次成本会随输出时长变化，Token 成本会随输入/输出 Token 变化，用户分组倍率、分辨率和视频素材也会影响收入与成本。因此目录查询必须以请求场景为输入，并复用运行时毛利计算口径。

## 目标与非目标

目标：

- 在成本核算页面增加独立的“路由毛利”视图。
- 默认复现 4 秒统计矩阵，并支持按分组倍率、时长、分辨率和素材类型动态计算。
- 支持最低毛利率筛选、排序、分页和导出。
- 返回预计收入、预计成本、预计利润、毛利率及不通过原因，便于审计。
- 保持现有供应商成本目录的查询、分页、排序和编辑职责不变。

非目标：

- 不修改渠道、成本规则或路由策略数据。
- 不改变实际请求路由、预扣费和结算逻辑。
- 不把离线统计快照作为唯一交互入口。

## 方案选择

### 方案一：扩展供应商成本目录

在现有目录接口上增加毛利率参数并关联路由目标。改动较少，但会把供应商成本管理与路由收益分析混在同一个职责中，且容易产生独立的计算分支。

### 方案二：新增路由毛利目录（采用）

新增独立接口和前端标签页，保留供应商成本目录的职责边界。查询服务关联活动路由目标、路由策略、有效成本规则和用户侧计费价格，并复用运行时毛利计算逻辑。该方案能同时覆盖固定统计口径和高级动态筛选，且不影响已有成本维护流程。

### 方案三：仅生成离线统计快照

实现最快，但数据更新后必须重新生成报告，无法满足页面内实时筛选和审计需求。

## 后端设计

新增只读接口：

`GET /api/cost-accounting/route-margin-catalog`

请求参数：

- `min_margin_ppm`：最低毛利率，默认 `300000`（30%）。
- `duration_seconds`：默认 `4`。
- `group_ratio`：默认 `1`。
- `resolution`：可选分辨率。
- `with_video`：可选；不传时返回 `no_video` 与 `with_video` 两个场景。
- `channel_id`、`model`、`route_target`、`status`：可选过滤条件。
- `page`、`page_size`、`sort_by`、`sort_order`：分页和排序。

查询流程：

1. 读取当前活动配置批次中的路由目标。
2. 关联路由策略、供应商成本规则和用户侧计费价格。
3. 按场景计算预计收入和供应商成本。
4. 使用 `(预计收入 - 预计成本) / 预计收入` 计算毛利率。
5. 应用最低毛利率筛选，并返回不通过原因。
6. 对按次、按 Token、按时长等成本模式复用现有运行时计算逻辑。

规则：

- 只读取当前活动批次和有效成本规则。
- 路由策略、成本规则或售价缺失时保留记录，标记 `eligible: false` 并提供 `failure_reason`，不得静默丢弃。
- 对非法或超范围的时长、分组倍率、最低毛利率返回 HTTP 400。
- 使用现有配额和价格转换工具，避免未经保护的浮点到整数转换。
- 返回分页总数、筛选条件和结果行，方便前端导出和审计。

## 前端设计

在“成本核算”页面新增“路由毛利”标签页，现有“供应商成本目录”保持不变。

筛选区：

- 最低毛利率输入，默认 30%。
- 快速模式 / 高级模式切换。
- 高级模式提供分组倍率、时长、分辨率和素材类型。
- 复用渠道、模型和状态筛选。

结果表格：

- 路由目标。
- 渠道 / 上游模型。
- 场景。
- 预计收入、预计成本、预计利润。
- 毛利率及达标状态。
- 不通过原因。

毛利率支持排序；达标和未达标使用明确状态标识；提供导出当前筛选结果入口，导出字段与表格一致。新增文案全部通过前端 i18n，覆盖 `en`、`zh`、`zh-TW`、`fr`、`ru`、`ja`、`vi`。

## 错误处理与兼容性

- 参数校验失败返回 400，并使用现有 API 错误结构。
- 无结果返回空分页，不视为错误。
- 缺失关联数据的记录仍可展示，并说明失败原因。
- 旧供应商成本目录接口和页面行为保持兼容。
- 数据库查询使用 GORM，兼容 SQLite、MySQL 和 PostgreSQL。

## 测试与验收

后端测试覆盖：

- 30% 阈值边界。
- 按次、Token、时长三类成本。
- `no_video` 与 `with_video` 分别通过或失败。
- 缺少成本规则或售价。
- 非法参数和分页排序。

前端测试和构建覆盖：

- 默认页面复现 4 秒统计矩阵。
- 30% 阈值下至少一个场景达标的目标数为 75，两个场景均达标为 60，仅部分场景达标为 15。
- 修改高级条件后重新查询并显示对应结果。
- 供应商成本目录原有流程不受影响。
- 所有 locale 完整，前端构建通过。

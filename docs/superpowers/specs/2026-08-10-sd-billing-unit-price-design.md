# sd 收录表新计费单价表头兼容设计

## 背景

最新 `sd收录` Google 表格调整了 `sd` 工作表的成本字段：删除 `元/秒`、`元/次`、`元/1M` 三列，新增 `单价 元` 列。I 列 `计费方式` 使用 `second`、`call` 或 `token` 表示计量方式，J 列 `单价 元` 表示该计量方式对应的人民币原始单价。生成器当前仍按三个旧列取价，因此无法读取最新版源表。

## 目标与边界

- 生成器只接受最新版 `sd` 表头契约：`计费方式 + 单价 元`。
- `second`、`call`、`token` 分别规范化为内部 `per_duration`、`per_request`、`per_token`。
- 三种模式均使用同一字段 `单价 元` 作为原始人民币单价，再沿用现有汇率、折扣、充值倍率和手续费换算逻辑。
- 旧表头不再兼容；缺失新字段或仍使用旧字段的工作簿在源表读取阶段失败，不能生成、导入或发布。
- 本次不改变 V1 模板的成本列、利润公式、导入状态机或运行时计费语义。

## 方案与选择

采用“源表边界规范化”方案：`source.ts` 负责严格验证并读取新表头，`build.ts` 只消费规范化后的 `计费` 与统一 `单价 元`。这样源表的列布局变化只影响解析边界，成本构建、模板写入和导入转换不需要保留旧列分支，也便于审计每条成本的来源字段。

不采用在 `build.ts` 继续分支读取新旧列的方案，避免旧契约泄漏到业务构建层；不采用把新表转换回三列旧结构的方案，避免生成结果掩盖真实源表语义。

## 设计

### 源表读取

`source.ts` 的结构化 `sd` 表头改为包含 `计费方式`、`单价 元` 的最新版顺序，并移除三个旧单价表头。读取记录时将 `计费方式` 规范化为内部字段 `计费`，并保留 `单价 元` 原始值供构建层取价；不在构建层保留源表列名分支。检测到旧三列、缺少新列、重复表头或新旧字段混用时，抛出可定位的 `sd header mismatch`，错误中列出缺失字段。

### 成本构建

`build.ts` 保留已有 `COST_MODES` 映射。`priceForMode` 不再根据模式选择旧列，而是解析 `单价 元`；模式只影响输出的 `CostRow.mode`、单位、计费事件字段和后续利润公式。单价必须是有限且大于零的数值；空值、零值、负值和非数值继续产生 `COST_PRICE_INVALID` 警告并将成本和映射置为 `draft`。未知计费方式继续产生 `COST_MODE_UNKNOWN` 失败。

### 测试策略

按 TDD 执行：

1. 先增加最新版表头的读取测试和三种计费模式的成本映射测试，确认旧实现失败。
2. 增加旧表头拒绝、新旧混用拒绝、缺失 `单价 元`、空/零/负/非法单价以及未知计费方式测试。
3. 实现最小解析与取价改动，运行新增测试及现有 `channel-model-template` 与 `channel-config-converter` focused tests。
4. 生成真实下载源表，执行源表和模板的结构、公式、视觉检查，并抽查按次、按秒、按 Token 三种利润结果。

测试只断言用户可观察的源表契约、成本模式、原始单价和 draft/fail 门禁，不锁定无关的内部列顺序或实现细节。

## 验收与回滚

只有在源表校验无公式错误、生成报告 `FAIL=0`、所有 `WARN/draft` 可解释、模板转换无 error、导入审阅及激活预检通过后，才更新仓库源表并执行本地 Mock Ark SDK E2E。真实供应商 Canary 不在本轮默认范围内。

本轮所有下载物、模板、报告、选中配置 JSON、导入问题和 E2E 日志写入唯一 `outputs/YYYY-MM-DD-<run-name>` 目录。任何阶段失败都保留证据并停止后续发布；仓库旧源表和已激活批次不因失败而改变。

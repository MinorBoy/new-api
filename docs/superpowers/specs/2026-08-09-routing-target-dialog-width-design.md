# 适配路由目标弹窗宽度设计

日期：2026-08-09

## 背景

“适配后的路由目标”弹窗需要同时展示筛选器、摘要、八列表格和分页控件。当前弹窗虽然声明了较大的 `width`，但基础 Dialog 组件在 `sm` 断点提供的 `max-width` 仍可能限制实际宽度，导致桌面端内容区域过窄。

## 目标

- 桌面端弹窗宽度固定为当前视口宽度的 `50%`。
- 移动端继续使用接近全屏的 `96vw`，避免半屏布局导致内容不可用。
- 保留现有最大高度、内部滚动、移动卡片和桌面表格切换行为。
- 不改变弹窗数据请求、筛选、分页和目标排除逻辑。

## 方案

在 `GroupRoutingTargetsDialog` 的 `DialogContent` 上使用响应式宽度与最大宽度约束：

- 默认断点：`w-[96vw] max-w-[96vw]`。
- `sm` 及以上：`sm:w-[50vw] sm:max-w-[50vw]`。

同时设置 `width` 和 `max-width`，确保覆盖基础 Dialog 的 `sm:max-w-lg`，使桌面端实际宽度稳定为视口的一半。

不设置固定像素上限，因为固定上限会让宽屏显示器上的弹窗低于用户要求的半屏宽度。

## 响应式行为

- 小于 `sm`：弹窗占视口宽度约 `96%`，内容区域按现有移动布局展示。
- `sm` 及以上：弹窗占视口宽度 `50%`。
- 表格保持现有最小宽度并在弹窗内部横向滚动，不允许撑宽页面。
- 最大高度继续为 `88vh`，目标列表仍在内部纵向滚动。

## 测试

更新弹窗布局回归测试，验证：

- DialogContent 包含移动端 `96vw` 的宽度和最大宽度约束。
- DialogContent 包含桌面端 `50vw` 的宽度和最大宽度约束。
- 现有筛选、分页、排除与恢复测试继续通过。
- 执行相关前端测试、定向 lint、类型检查和生产构建。

## 非目标

- 不修改弹窗高度。
- 不修改表格列、分页数量或筛选器布局。
- 不新增用户配置项。
- 不改变其他 Dialog 的默认宽度。
